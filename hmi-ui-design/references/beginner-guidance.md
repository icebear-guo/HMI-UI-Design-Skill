# 弹窗启动、HTML风格选择与全程引导

这是助手执行的流程。用户只调用技能即可开始，不需要学提示词、技术表格或内部阶段名。处理技能更新/评审的元任务时，不误启动HMI项目；已有项目与局部修改沿用实际上下文，不重复起步问卷。

## 弹窗必须是真实交互工具

根据当前宿主工具清单，调用实际可用的交互提问工具。本环境可用`request_user_input_async`；其他宿主使用其实际提供的同类工具，不编造工具名，不把只在特定模式可用的接口强行用于当前模式。一组问题尽量在一次弹窗里展示，支持普通文字输入和选项；长段落、Markdown列表、普通聊天问号均不等于已弹窗。

工具发出后等待实际提交。默认高亮、预选项、时间经过或未回答不算用户选择。只能继续与答案无关的资料整理，不能先生成假定行业、选定风格或整套页面。

如果宿主确实没有可用提问工具，简短说明“当前环境没有弹窗提问能力”，报告具体缺项；不能声称已经弹窗或静默退回长问卷，也不改全局配置伪造能力。用户决定其他交互方式后再沿相同信息顺序兼容。技能安装/列出本身不是任务事件，需要宿主实际调用技能。

## 流程一：起步三类问题 → 实际HTML

首次无需求调用时，简短说明将先收集屏幕、设备和制作范围，随后实际调用提问工具：

| 提问 | 输入方式与帮助 |
|---|---|
| 请选择触摸屏的尺寸和分辨率；其他型号可自行填写，不知道可填型号或待定。 | 四个选项：7英寸／800×480；10.1英寸／1024×600；12.1英寸／1024×768；15.6英寸／1920×1080。保留宿主的自由输入入口，不只给一道自由填写题 |
| 用于什么行业/什么设备？ | 自由填写设备名或用途，例如“油漆固化烘干箱”。可只说设备，助手整理行业；没有设备依据不自行选演示行业 |
| 这次希望先做哪一步？基础5页包含运行总览、手动操作、参数设置、报警记录、IO监控；6页另加设备维护，也可以自定义。 | 选项：先看运行总览的不同布局/色调（建议）；直接制作基础5页；直接制作6页（含设备维护）。宿主若支持自由补充，可填其他范围 |

三类信息在同一轮收集，不再退回test3“只问设备一个问题”的入口。已有明确答案时带入并只补缺项；不为了凑三问重问。不能附加PLC、变量表、MCP路径或长工程问卷作为启动条件。

### 首轮屏幕的四个常用组合

按用户提供的型号资料设置以下快捷选项，英寸和分辨率一起显示在实际弹窗中：

| 选项 | 屏幕对角尺寸 | 原生分辨率（宽×高px） |
|---|---|---|
| 1 | 7英寸 | 800×480 |
| 2 | 10.1英寸 | 1024×600 |
| 3 | 12.1英寸 | 1024×768 |
| 4 | 15.6英寸 | 1920×1080 |

支持四个选项的宿主直接使用四项单选，并允许自由补充其他尺寸/分辨率/型号或不确定。宿主自带自由输入入口时使用该入口，不占用四个预设选项。若宿主单题只能给三个选项，在实际弹窗题干列出以上四组编号，允许输入编号或自填；不能静默删去第四组，也不为选屏幕再展开多轮问卷。

用户明确选中组合后，同时记录对应英寸和像素，继续同轮的行业设备和制作范围，不重复问分辨率。用户自填参数优先；只说“7寸”等未明确选择组合时，不推定分辨率，可结合型号核实或只补问缺项。这四组是常用预设，不表示所有同英寸设备的分辨率相同；800×600、1366×768、480×272等其他已支持分辨率仍可自填。

### 页名与后续制作

页名说明必须出现在实际弹窗的题干或说明字段中，不能只保留在本文件或发送工具前的聊天里；短选项可以写5页/6页，但用户作答时必须能同时看见具体页面。IO监控即IO界面，可在说明中写“输入/输出信号状态”。这是默认组合，用户可以增减、改名或自定义。

答案足以制作视觉预览后，直接推进实际HTML，不在工艺追问中无限停留。只有缺项会改变设备结构或使预览无法成立时，集中补问必要问题。未知温度、阈值、箱体形式、加热方式等使用明确“示意/模拟/待核实”，不得当作客户已确认。

屏幕待定时提出暂定画布并取得相应选择。当前原生复制支持480×272、800×480、800×600、1024×600、1024×768、1366×768、1920×1080；按用户实际宽高制作，不按16:9替换。不知道分辨率时可参考型号后补；范围外需求保留并说明待适配，不能偷偷改尺寸。具体规则见[分辨率适配](resolution-adaptation.md)。

### 分支A：先看运行总览方案

按本项目行业/设备与同一组示意内容，默认制作左侧导航、底部导航两种可打开的运行总览布局，并提供四种实际色调切换/组合，实际检查后给HTML入口。两种布局的内容位置与阅读顺序有可见差别，不能只换标题或只换颜色。可在一个HTML中展示八种组合而共用业务源，不要求八份独立页面或八个原生窗口。素材、图形、布局及色调仍可新增、自定义，客户指定优先。顶部状态栏、报警条和内容容量按[默认布局规则](default-layout-rules.md)执行。

候选有清楚的编号、布局说明和色调名称，便于下一步弹窗选择。没有实际HTML时不能要求用户确认“已经看过的方案”。本分支此时只做风格代表页，不擅自生成整套。

### 分支B：直接制作5页/6页

首轮明确选择直接整套，表示按已知设备与所选范围制作；助手可先自主完成代表页的内部检查，再继续全部页面，不插入用户未要求的风格审批。未知风格可以由助手提出并标为建议/委托，不写成客户看过后确认。

已选5/6页即沿用，不重复问页数。交付实际逐页HTML供查看、选择修改，仍保留风格调整和局部编辑。明确选择直接整套不授权猜PLC地址、设备安全逻辑或其他未知硬件定义。

MCGS项目的制作沿用模板结构与独立素材，在同一项目源先贯通代表页预览、编辑及复制，再展开所选页面。用户看到的正式预览直接就是可编辑、可复制入口，不在整套HTML完成后追加“是否再制作MCGS可粘贴版”的选择，也不让用户再次审阅一套重建内容。代表页内部检查不增加用户审批轮次；真正缺型或未实现逻辑明确列出。

## 流程二：看过HTML → 弹窗选择/修改 → 确定页数

先提供已检查可访问的候选入口和简短观看要点，再调用交互提问工具：让用户选择实际方案编号及布局/色调，或者提出修改。选项必须对应刚交付的实际候选，并保留“修改/混搭”的表达入口；工具选项数受限时分成同轮少量相关问题，不直接去掉修改选项。

默认将布局与色调分成同轮两题：布局选左侧导航/底部导航，色调选实际展示的四种；允许通过自由输入修改或自定义。不要把某种色调锁定为只能配某种导航。选择后沿用对应源与参数，继续既有页数分支，不重新制作独立原生版。

- 选定某一方案：记录实际方案ID/版本、用户回复和适用范围。
- 混搭：如“A布局+B色调”，先生成组合后的实际HTML再请用户查看，不把混搭想法当作已经确认新画面。
- 要修改：集中补所需改动，修改并提供新版本HTML，再弹窗询问是否采用/继续修改；保留其他已确定项。
- 尚未查看/未决定：保留选择待定，不推进已确认风格或自动套首个选项。

用户确认当前布局/色调后，若首轮只选“先看方案”，再弹窗询问整套页数：

实际弹窗题干可写：“接下来制作哪些页面？基础5页为运行总览、手动操作、参数设置、报警记录、IO监控（输入/输出信号状态）；6页再增加设备维护，也可自定义。”选项为基础5页、6页（加设备维护）、自定义。此处再次列明页名，不能假定用户仍记得首轮说明。

| 范围 | 默认页面 |
|---|---|
| 基础5页 | 运行总览、手动操作、参数设置、报警记录、IO监控（IO界面） |
| 6页（加设备维护） | 上述5页＋设备维护 |
| 自定义 | 用户指定页数/页名；允许单页或其他范围，不为凑5/6页扩张任务 |

五个基础页是通用设备整套的默认起点。趋势图可加入适用页面或按用户要求另增页，不能擅自用“温度曲线”等页替换IO等基础页。若用户早已明确其他数量或指定页面，按其实际要求，不强推默认方案。

页数确定后，由助手按设备用途整理每页具体内容、公共组件与素材复用，展开整套HTML。不要让用户自行编写逐页策划，也不要重复确认刚提交的答案。

## 已知、建议、模拟和确认分开

用户说“烘干箱”“油漆固化”，能直接记录的只有这两项及其来源。温控/固化行业可以标为助手推断；单箱/隧道式、电加热/蒸汽、温度范围、联锁、页数、方案选择都不能凭这两个短答写为“已确认”。示例值只用于示意，标模拟；关键真实定义待后续核实。

只有用户实际说过/提交过的内容才记为用户提供；对实际画面的选择、反馈或明确委托按真实范围记录。上一轮的问题没有被回答，不自动视为同意。存在矛盾时只补问该项，不在一段话中把同一属性同时写成“已确认”和“待核实”。

先看风格分支尚未决定总页数时，先保留预览评审消息、实际文件与暂定范围，不为让正式workflow检查通过而编造页数或确认。总页数确定后再用记录工具建立对应的正式范围，沿用仍适用的真实选择证据；不要求客户重复选择未变的风格。

## 后续环节继续引导

每次给出当前实际成果、用户现在怎样操作，以及下一步会得到什么。关键选择优先用弹窗；仅补当前必要缺项，不在每轮重打整套问卷。普通用户可以用“不知道”“你建议”或直接描述动作来回答，助手负责提炼设备、功能与素材。

整套HTML给真实页名和切换入口；局部编辑说明开关、选中对象、字段和应用按钮；复制说明目标位置；原厂核对集中进行；交付只指向当前成功入口。用户中途要求修改时处理该处，保留其他已确认成果。

## 预览和修改：给能照着做的步骤

提供已检查可访问的预览入口，并说明“这是可以点选修改的预览”。项目启动器写清实际文件名；链接打不开时先检查本地服务和会话，不直接让新手自行排查端口/依赖。

首次编辑时按当前网页实际控件解释，最多给三四步。文字/数值修改使用统一尺寸工具；碰撞提示发生时由助手帮助调整布局，不让新手猜字宽公式或盲目缩字。用户说“这里不对”时先定位具体对象/截图/文字，保留其他已确认内容。

如果用户不想自己操作编辑器，继续用自然语言反馈，由助手修改。自助编辑是加快迭代的选项，不是把修正责任交给用户。

## MCGS复制：首次要讲清的事情

首次进入复制环节，按本次实际对象给步骤，不同时混讲所有路径：

- 完整窗口：在网页勾选需要的页→点击“复制所选完整窗口”→回到MCGS组态的“用户窗口”列表粘贴。不是在已打开画布粘贴。
- 页内控件：网页复制当前页或选中控件→打开MCGS目标画布粘贴。粘贴会新增对象；替换旧对象由用户核对，不冒充自动覆盖。
- 默认未绑定：显示可能是0/0.0，输入可能为空，这是待设置变量的状态，不要求用户反复重复制。网页模拟值、组态占位文字和运行值分别解释。
- 分辨率：粘贴前核对工程屏幕规格与本次设计尺寸相同；更换规格前先另存测试副本，MCGS可能同时缩放既有窗口和控件。批量测试时每个尺寸保留自己的保存副本和运行截图，避免最终工程覆盖前面尺寸的坐标证据。
- 名称方式：用户选择此方式后，才说明同名变量、MCGS校验/编译和待解析身份；不在空白启动阶段要求变量表或MCP路径。

粘贴失败时先确认目标位置、是否仍在模拟器、复制内容是否被其他操作覆盖，必要时帮助重新生成/复制；不让新手一次重做整个项目。只有确实需要回读用户已保存工程时才询问保存位置，不能将MCP路径作为新设计前置。

## 原厂验证与交付：少打扰，结果说清

给与本次变更相关的一轮检查，不把所有历史项目的测试清单照搬过来。能在网页和结构侧自行检查的先完成，再请求必要的原厂操作。用户提供运行截图时先分析截图；缺哪项证据只补哪项，不重复问已经确认的步骤。

出现0值、空输入、报警条无消息、组态占位数字时，先结合绑定状态解释，不一律判为导出失败。数字末位改变先核对格式和自然小数，再判断裁字。工具检查、组态显示、运行截图及设备动作分别报告，不能为了让流程看起来完成而猜测通过。

交付时只给用户当前需要的入口、简短操作和已完成/仍待核实项。用户不需要学习目录结构、版本哈希、JSON字段或提示词写法。保留必要源文件和技术证据供助手后续维护。

## 在全新会话验收引导

首轮屏幕检查：四个常用组合应能在实际弹窗中选择，且显示对应像素；自填参数与型号入口仍存在。选定组合后不重问英寸/分辨率，自填其他已支持分辨率不被强改为四组之一。预选高亮仍不代表已提交。

实际测试应在无项目记忆的新任务里，只调用本技能，不附项目提示词。应真实弹出屏幕尺寸/分辨率、行业设备、先看方案或直接整套这三类问题。第一轮不能只有普通文字或单独问设备。分别测试“先看方案”和“直接5/6页”：前者看实际HTML后弹窗选择/修改，再选页数；后者沿用首选范围，不重复问页数或插入未要求审批。

检查首轮制作范围弹窗，以及先看方案分支后续页数弹窗：用户作答前应能看见基础五页的全部名称、六页增加设备维护，以及可自定义的提示。只有内部文档写有页名或助手在普通聊天里解释，不能算弹窗已说明。

再测试只说行业、说“不知道”、要求混搭、改字段、说“贴不进去”、反馈0值等情形。检查五个基础页是否都在、是否擅自替换IO，短答是否被扩写成虚假的“已确认”。不能以结构校验通过代替真实弹窗与用户流程运行。

技能结构/链接检查不能证明模型实际会遵循向导，也不能证明每个宿主选择技能的UI都会自动发送；实际新会话结果单独记录。不要把本文件内的示例对话或预期行为当作已经执行过的测试。
