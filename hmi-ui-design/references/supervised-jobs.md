# UI + MCGS 长任务分阶段执行

适用于已要求的设备/零件多页 UI 到 MCP 全链路。普通 UI 单独导出、纯 IO、局部编辑继续原有流程，不凭页数固定扩任务。

配套通用skill `hmi-mcgs-supervisor`，入口 `python scripts/run_supervisor.py --help`，操作细节和合同示例见总控skill的README。两个 skill 保持1.05；同一总控器维护放行逻辑，不在各 skill 各写一套规则。总控skill安装在同一宿主的skills目录，或通过HMI_MCGS_SKILLS_DIR配置根目录；doctor自动检测本机依赖，缺少时明确提示安装配套skill，不自建假的通过报告。

总控从立项时就协同本技能制定任务、执行要求和验收标准，先运行plan输出任务计划/执行验收矩阵/模板能力风险，在流程1实际确认或明确委托后，按用户真实范围冻结合同（页面、公共页、最低组件、系统/设备/零件拓扑与端口、公司名、模板、样例范围）。将已审合同副本存00_parameters/job-brief.json，执行 `init`；代表图鉴→代表页→方向确认→完整图鉴/全套UI，每次 `next` 获取一张工单，完成后 `check`；失败补齐当前关，不能跳关或缩减合同/上游 inventory。客户评审仍按 project-workflow；总控器机器放行不等于客户确认。

UI 负责流程图、独立图鉴、样例及完整 HTML、标注、冻结源组件清单、独立 PNG 和完整 schema1.05。公共窗口导航/状态栏在设计时属于公共页；页面实际预览保留组合。通过 HTML 的 data-hmi-* 标记让控制器读取真实可见 DOM，详细字段见总控skill的README。不能用隐藏标记、空矩形或未标记画布冒充完整设备/组件。

最终导出选择有效后才正式渲染生产 PNG；总控器素材关和导出关都会复查实际项目记录。控制器调用固定 export_handoff 导出权威 mcgs-plan/CSV/资产，交给 MCGS skill 的是回执定位的目录及哈希，不靠猜“最新文件”。制作方自填 validation/pass 无放行效力。

每关自动保存报告与秒数；项目 MD 记录实际产物、失败原因和下一步。上游变更需新 job，不能改回执接着算通过。逐项伪3D质量、真实交互和视觉盘点仍需各自实际验证；DOM 只能核对已标注组件，不证明不存在未标注图形。

同一 Windows 账户只能做完整性检查，无法防止代理整体改写代码和证据；不得宣称已实现权限隔离。原厂显示/组态/编译/运行也不由 UI 或 DOM 通过代替。

未确认不能自行标delegated。图鉴结构检查不认证伪3D精致程度；先实际审阅代表设备和代表页，方向稳定后再扩批。新增binding语义在计划/样例阶段明确，最终规格沿用；不把物理PLC地址与本地演示变量混为一谈。

当前流程视觉归用户：不再强制AI对图鉴/代表页做美术复审。当前page_sample/ui可先preview做整数可导出几何、版本/字段等技术检查，不冻结；用户确认方向或完整界面后再check冻结。绑定枚举直接复用handoff_policy，非法access/signal_role在规划阶段拒绝。确认前的UI源可迭代，避免视觉小改引发全job返工。
