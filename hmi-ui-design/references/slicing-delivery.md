# 切片与工程交付规则

完整UI项目正式切图须先完成 [C1/C2/C3客户确认](project-workflow.md)，并运行 `check_project_workflow.py --for slicing` 核对项目记录。未全部确认时只交HTML评审稿，不提前渲染页面/组件PNG，不得以验证管线为由先切片。单项偏好、工具自检或部分页面确认不能放行整套输出；自编脚本同样遵守此边界。

## 最终切图范围

以C3已确认的全套HTML为基准，逐页盘点全部可见图形、组件子层和必要状态，再对照 [元素覆盖规则](asset-coverage.md) 确定交付。清单从画面中应有的元素开始，不能只登记已经导出的文件。C3评审期间可先提供HTML盘点和拟交清单；C1/C2/C3全部确认后才正式导出PNG。

| 内容 | 默认最终交付 | 完整性要求 |
|---|---|---|
| 人形、装饰、导航、警告、通信及其他图标 | 各自独立PNG；有可编辑矢量母版时另附 | 图标虽用CSS或SVG画在HTML中，仍纳入交付；不能只交底板或让工程端自行寻找替代图标 |
| 独立小状态灯、PLC通信灯、IO LED、设备大状态灯 | 按本次已定义语义提供所需状态的独立PNG | 区分小灯与大状态灯，不能用一组大灯资产代替所有独立灯；动态灯态不得合入静态背景 |
| 按钮底板、按钮图标、面板、弹窗、背景及装饰图形 | 按构成层提供独立PNG | 保留父组件、层级、锚点和实例关系；按钮底板的s0/s1不能覆盖或代替图标子层的交付 |
| 设备图、插画、材质与复杂背景 | 按用途导出独立PNG，并保留可提供的母版 | 明确透明需求、实际尺寸和使用范围；约定使用其他格式时记录依据 |
| 多状态图形 | 同画布、同锚点的状态组 | 规定状态逐一覆盖，不能只出常态或用同图改名充数 |
| 标签、实时数值、趋势采样及其他动态数据 | 原生文字/数据绑定、绘制或控件规格 | 不要求每个字或采样点导出PNG；图表的静态底板、图标与装饰仍单独盘点 |

图形采用目标平台原生实现、仅交矢量或明确合入某个静态背景时，属于逐项交付例外：必须交付可复现的实现规格或父资产映射，并取得客户针对当前范围的明确确认。不能只写“native”“可替换为平台图标库”“CSS可绘制”或“不单独导出”。原生规格至少说明目标控件/平台适用依据、尺寸、颜色、绘制/控件参数、所需状态及其映射；背景合并说明父资产及覆盖位置。目标平台能力未知时保留未决，不能自动豁免。

共享资产可以只导出一份，但每页的图层/实例都要引用它。不得把整条状态栏、整张卡片或整页记为一行“原生内容”，从而掩盖其中的人形、通信、警告图标与指示灯。最终每项必须已导出，或有有效的客户确认例外；任何未决、缺失、悬空引用或缺态均阻止完整交付通过。

先核实平台支持的格式、位深、alpha、缩放、资源容量和命名限制；未确认时列为待验证项。SVG、RGBA PNG、WebP、九宫格、图集等都不能被视作所有 HMI 工具链通用能力。

## 坐标与母版

- 母版保留原始文件，记录实际宽高、文件哈希与来源。生成图、抠图和缩放图分别标识，不覆盖母版。
- 切片坐标以实际母版像素为准：左上角 `(0,0)`，`rect_px=[x,y,w,h]`，右边界 `x+w` 和下边界 `y+h` 不含在矩形内；坐标使用整数、宽高为正、范围不能越界。
- 屏幕坐标、设计坐标与源图坐标分开记录。存在缩放/平移时明确换算及取整方式，不把设计稿标注直接当原图坐标。
- **预览图不决定工程尺寸**：用设计标注的 artboard/画板尺寸对照实际预览文件，分别计算 `sx=预览宽/设计宽`、`sy=预览高/设计高`；两者不同先检查裁边、缩放或错图。图层矩形只在倍率与原点关系已核实时换算为预览裁框。独立导出切片另查其导出规格，不能继承整页预览倍率；导出查看器的 CSS、zoom 或全局 `scale` 字段也不能替代实际比对。
- 裁切前查看图像并确认范围，给描边、柔边和投影留出明确的 padding。默认不自动紧边、不按非透明包围盒裁掉空白；状态组需要相同空白与锚点。
- 截图里的文字、数值、状态灯与背景已经合并时，裁切不能恢复可编辑图层。切片仍带邻近内容或背景时重新制作独立资产，不能宣称已经分离干净。

## 透明与画质

- 透明资产以实际 alpha 通道为依据。仅存在 RGBA 模式不代表已透明；应检查 alpha 最小值/最大值与透明像素数量。
- 需要透明的交付件应在深底、浅底上检查白边/黑边、杂色、孔洞和投影。禁止将真实发白设备当作白色背景一并删除。
- 切片操作只裁切；抠图、去底、重绘、缩放和格式转换是另外的派生步骤，要单独记录。禁止用“切片成功”掩盖抠图尚未完成。
- 栅格文件以目标显示像素导出。放大前说明来源与用途；像素尺寸增加不代表细节恢复。照片与插画按等比原则处理，只有明确可拉伸的边框/纹理才能按项目约定拉伸。

## 命名与状态组

推荐：`<page>__<component>__<state>__<w>x<h>.png`。只用稳定的英文小写、数字、连字符与下划线；按工程工具要求调整。避免空格、大小写区分冲突、中文编码问题、路径越界和平台保留名称。

状态命名按语义分离：`default / pressed / selected / disabled / pending / running / stopped / warning / fault / offline / stale`。这些只是词表，按实际组件选用；按钮按下态不能代替设备运行态，离线不能使用停止态来冒充。

新设计按钮以 `s0/s1` 成对导出，建议命名为 `<page>__<button>__s0__<w>x<h>.png` 与对应 `s1` 文件。映射表写清 `s0=常态`、`s1=交互反馈态`；瞬时按下/松开与导航持续选中分别定义。两态缺一、不一致尺寸或视觉完全相同的按钮不能算完成交付。图层组件ID、两态资产与命中区域必须对应。

同一组件组必须有一致的像素画布、设备位置、基线与锚点。多状态需要的画面内容即使大小不同，也放在相同尺寸的透明画布上，不单独紧裁。热区由工程组件定义，文件的透明留白不自动成为合法热区说明。

导入既有 `s0/s1` 等编码时保存在 `raw_state_code`，不直接推断其原始工程语义。[状态映射表](../assets/component-state-map.template.csv) 单独记录所属维度、语义、绑定/反馈依据与核实状态；菜单选中、按钮按下和指示灯状态不能混为一谈。旧资产缺少依据时保持 `unmapped`，并补全后再作为正式按钮交付；新设计按本规范直接定义双态。

组件切片按构成层交付：`background / control_plate / icon / indicator / device_illustration / brand` 等角色分开；文字和实时数据留在可编辑层。底板＋图标＋文字的组合需有组件 ID、锚点和层级说明；已有独立原片时优先核验复用，不从大预览再次裁出低质量副本。历史品牌图和字体只留作来源材料，不自动替换当前品牌与字体。

## 资产清单与交付

用 [元素覆盖规则](asset-coverage.md) 将已确认HTML中的元素与交付方式、资产及状态逐项对应，再用 [交付清单模板](../assets/delivery-manifest.template.csv) 记录每个实际文件；两份清单互相核对，不能只交一张拼图。文件字段包括资源 ID、页面/组件/状态、导出路径与格式、实际尺寸、alpha 需求与结果、原图/裁切矩形、原图与输出哈希、锚点、来源使用权限、允许用途、版本与验证状态。`design_size_px / export_scale / asset_role / raw_state_code` 区分逻辑尺寸、位图倍率、构成角色和历史编号；未知项写未核实，不能倒推后冒充原始标注。无裁切来源时明确标记不适用。

检查既要核对已列文件是否存在，也要逐页对照已确认HTML检查元素盘点本身是否完整。机械检查无法识别从未录入的可见元素；漏记图标不能因包内文件对账成功而写为全部通过。

每项任务按需要包含：

1. 可编辑源或生成母版，以及可以直接导入的独立文件。
2. 页面预览或资产联系表，透明件同时提供深浅底审阅；联系表不替代单文件。
3. 参数、坐标清单、资产清单及校验结果；记录目标平台上实际做过的导入验证。
4. 工程映射说明：组件 ID、数据类型/单位、状态映射、权限、待确认地址。只在用户或工程资料提供时填写真实 PLC 标签与地址。

完整 UI 设计按 [交付包规范](output-package.md) 组织 `index.html`、`preview/`、`assets/`、`fonts/`、`specs/` 及配套清单，并提供同名压缩包。HTML须提供 [功能原型](interactive-preview.md) 与设计标注。实际可编辑源和检查记录可另附；避免同一资产重复复制后独立修改。HTML不能只链接整图或弹出标注，独立切片也不能由联系表替代。

## 切片工具

批量矩形裁切可用 `scripts/slice_assets.py`，契约与命令见 [slice-tool.md](slice-tool.md)，输入模板见 [slice-manifest.template.json](../assets/slice-manifest.template.json)。先 dry-run，再写入新的输出目录，检查实际结果后交付。该工具不会识别部件、去背景、生成状态图或自动对齐；这些能力不能写入其完成报告。
