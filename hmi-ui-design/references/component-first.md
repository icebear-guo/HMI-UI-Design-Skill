# 组件先行：设计即为导出源

## 独立组件交付是默认硬约束

本 skill 的新设计保留背景、布局、灯、文字、按钮、装饰色块、装饰图标及设备子层。**不得把多个应独立组件烘焙到整页背景来减少素材或控件数量。** 静态不等于可合并；组合关系不等于扁平化。页面背景只画其自身的底色/纹理，不承载独立面板、分隔线、导航、图标、设备、状态灯或文字。

“模板没有图片控件”“矩形颜色未标定”“图形是组合关系”“没人会拖动面板”“交付是可运行工程”“像素逐项一致”“控件太多不好维护”均不能自行改变交付范围。控件数量/性能的取舍需目标平台真实数据和用户对具体变更的明确决定；不能把猜测的上限或维护成本当硬约束。

内置原生结构缺型时，只限制该项复制，保留通用源与独立素材并列出缺项。不因缺型省略设备图鉴，不用假灯或整页背景替代。颜色未支持的独立图形可渲染自己的PNG并使用真正图片控件。

源组件清单在流程3确认前冻结；逐项记录页、组件、角色、实例/母版、状态、源节点、输出文件或已验证原生对象。交付必须给出“源组件数 → 独立资产/合法共享资产 → 原生对象”对账。页截图、控件位置或图片像素一致只能证明对应检查，不能证明全部图形独立交付或原厂可运行。

默认完整交付不接受 merged 模式。用户另行明确要求扁平图时可提供该范围的派生件，但必须标注结构损失，不能代替本 skill 的分层交付或把原源清单缩成几个背景组件来通过检查。缺项记 fail/partial，并给出实际缺失 ID，不说“并非漏做”。

项目需要设备插画时，先画系统/设备/零件流程关系图，确认层级、连接、方向与端口，再按 [精致伪3D设备图鉴](equipment-atlas.md) 的规范与提示词，将每个设备/零件独立绘制成精致伪3D图鉴；不省略、不给方框代替设备/零件。最后按流程关系逐台、逐件组合，保留独立源组件。流程关系图不等于最终设备插画。

## 在流程1～流程3就确定结构

流程1确定页面/任务、共享区域、设备和状态；流程2用代表页验证组件家族与文字归属；流程3完成全套同源组件树、交互与逐组件导出映射。确认前保持 HTML/CSS/SVG 可编辑，不提前生产 PNG；导出在相应确认之后执行。

背景图、布局图、灯、文字、按钮、装饰色块、装饰图标分别建层或组件。每个都有稳定 ID、页 ID、局部矩形、绝对矩形、父 ID、z 层次、锚点和角色。同一个母组件可有多个实例，各实例有自己的位置、变量与状态；不要靠一次性大图省略实例。

导航不是一个待分割的长条，而是 `nav_overview`、`nav_process` 等独立按钮组件。每按钮内含底板/图标/文字子层，并有 s0/s1、命中框、目标页。共享导航、通信与报警条由共享组件实例引用，不在每个业务页复制多份。

## 流程关系先行，再逐项图鉴与组合

本节用于实际需要设备插画/工艺关系的任务；纯IO、参数页或局部文字编辑沿用本次范围，不强加设备图鉴。

先绘系统/设备/零件流程关系并冻结节点清单，再逐台、逐件完成泵、阀、罐、风机及所需零件的精致伪3D母组件与状态，最后按同一流程图拼装。多设备组合保留 system → equipment → part → graphic/indicator/text 的结构；允许组合预览，禁止只剩整条生产线的扁平位图。

管道段、箭头、液位填充、机械外壳、运行/故障灯、设备名、单位和数值是不同语义层。会随变量变化的层不得烘焙进静态机械插画或底板。箭头如有动态状态独立给状态组；固定箭头也保留自己的组件与导出映射。

## 文字的视觉层与工程归属

多段信息默认独立工程控件。按实际可见行/文本块建标签，不固定生成三个；同一卡片的底板为独立布局图片。动态0/1或读数用独立变量绑定的文字/数值显示元件，不能写成静态标签。一个真正段落需要整体换行时，可明确声明为单个多行标签；不得借此把不同位置、字号或语义的编号/值/说明合成一个控件。

| 设计 | 组件树 | 工程归属 |
|---|---|---|
| 信息/IO卡片上的编号、0/1、通道名称 | 独立布局底板＋逐段文字/数值组件 | 编号与名称为独立标签，动态0/1为独立绑定元件；状态灯另建，底板不能冒充灯 |
| 圆灯旁写 PLC 通信正常 | 独立灯组件 + 独立文字层 | 指示灯与外部标签分别创建 |
| 按钮上的启动/停止文字 | 按钮内文字子层 | 按钮各态原生文字，不另加外部标签 |
| 数值后面的单位 | 数值元件内单位或独立文字层，明确二选一 | 明确归属及间距，不能两边都画 |
| 数值控件专属纯色/圆角底图 | 独立皮肤源层＋同一数值组件owner | 有已验证图片槽时绑定进数值控件；不额外生成一个底图原生对象 |

按钮的单段caption留在同一按钮；明确要求的灯内单段状态文字可留在灯内。默认不生成同一灯的多条文字子项。只有用户明确要求多条内嵌，且当前原厂版本已验证各条实际显示不重叠时，才声明 `native_multi_text_layout_verified` 并引用证据。仅序列化回环、局部框/父框/double rect相等或离线合成图正常不足以证明原厂多文字布局。

每个文字层都输出完整内容、字体、px 字号、字重、颜色、对齐、行距、框尺寸、页面/局部位置、状态和 text_owner。图形与文字分别建模，生产 PNG 默认不含原生文字与动态读数。

独立源层不要求一律对应额外原生对象。数值专属皮肤保留ID、同源SVG/PNG、native_owner、图片槽和像素尺寸；更改类型或尺寸时皮肤跟随owner。共享面板、图标和设备层保持独立，不能把本条扩大成合并整卡片或整页的理由。普通标签、动态读数、数值输入按用途分型；位操作、导航及非位业务动作按实际语义匹配工厂。

## 直接渲染，而非事后分割

组件具有独立 HTML/SVG/矢量/场景节点的导出入口；用同一组件源生成页面组合预览和该组件状态 PNG。无需先把页面变成大图再恢复组件。SVG 母版、必要依赖和组件导出函数与清单一并保留，避免导出时手工重画一套与评审不一致的图形。

按钮底板、图标、灯态、装饰块等按角色独立导出并记父关系。工程需要某个组件的合成皮肤时，也从子层直接合成导出，保留各子层及合成映射，且不得混入应由原生控件呈现的文字或状态点。

既有扁平图仅能作为参考或经授权的迁移来源；裁切恢复不了缺失图层。发现灯、文字、按钮已烘焙在底图中，回到组件源修正并重新渲染，不能把切割矩形变细当作解决。

## 设计检查与导出检查分别执行

设计检查：每个导航按钮是独立组件；设备可独立移动/换状态；隐藏任一灯/图标/文字后其他层不变；背景和布局源不包含这些层；文字归属清楚。

导出检查：从应交元素盘点开始，逐项核对母版、实例、所需状态、文件、1:1 尺寸、锚点、透明及 SHA；不能仅遍历已经导出的文件。重组预览与确认的组件源对照，检查重复图层、漏图、文字截断与非预期重叠。需要由人工确认的视觉完整性，不伪称由文件对账证明。

源库存包括组合设备和按钮母版内部可独立编辑的子层，不只列顶层MCP控件。图元子层、导出asset、原生对象分别映射，数量不要求相等；合法复用保留逐实例关系。默认公司标签由branding.text_refs跟踪，和项目标题分别建模。实际PNG渲染/有效内容/最终重组按 [export-validation.md](export-validation.md) 检查。
