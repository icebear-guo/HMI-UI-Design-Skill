# HMI UI 设计与交互规则

本文用于工业设备触摸屏、产线操作站与 SCADA 的界面设计、实施交接和评审。它是项目设计方法，不是安全控制设计文件、标准全文或合规认证。遇到医疗、交通、航空等专用领域，需要另行确定适用要求。

数值起点见 [`../assets/design-tokens.template.json`](../assets/design-tokens.template.json)。该文件的 `proposed` 候选值，包括 1280×800 画布、8 px 栅格、16/20/24/32 px 字号和 48 px 候选触区，都必须在具体设备与使用条件下验证。不得把这些候选值称作行业强制标准，也不得仅因截图好看就标记为已验证。

## 1. 先确定任务与约束

按以下顺序处理冲突，并在交付中记录取舍：

1. 已批准的设备安全要求、操作规程、报警策略与适用法规/合同要求。
2. 操作员能否识别设备真实状态、理解后果并完成关键任务。
3. 信息可读性、触控可靠性、异常与失败反馈。
4. 平台可实现性、性能、维护与多语言扩展。
5. 风格统一、品牌与装饰。

不要自行推断工艺安全限值、联锁逻辑、报警优先级或谁有权远程启停。缺少这些输入时，可交付带假设标记的演示方案；对应控制逻辑与参数标注“待设备/工艺负责人确认”。

建立一页项目约束表，至少包含：

| 类别 | 需要记录的输入 | 对设计的影响 |
| --- | --- | --- |
| 使用者与任务 | 操作员/维修员/管理员；高频任务；异常处置；是否培训 | 导航、术语、默认页面、权限 |
| 屏幕 | 原生像素、有效物理宽高、方向、DPI/缩放、可用显示区 | 文字物理尺寸、布局、资源导出 |
| 现场 | 观看距离、安装高度/角度、照度与反光、昼夜、振动 | 字号、对比度、主题与识别测试 |
| 输入 | 手指/手套种类、鼠标/键盘、触屏类型、触点精度 | 热区、间距、输入方式、防误触 |
| 工艺 | 设备/工位层级、主要变量、动作后果、现场/远程模式 | 画面结构、状态模型、操作流程 |
| 通信 | 更新周期、时钟来源、质量位、断线行为、命令回执 | 陈旧阈值、延迟提示、禁止条件 |
| 平台 | 型号/版本、色深、字体、SVG/PNG/透明度支持、内存与刷新限制 | 控件、动效、切片与降级策略 |
| 交付 | 目标分辨率、语言、工程软件、原生控件、资源预算 | 文件类型、命名、清单与验收 |

## 2. 物理可读性与触控验证

- px 是显示/实现单位，不能直接当作普遍物理尺寸。先确认应用像素是否等于面板原生像素；浏览器 CSS px、系统缩放、DPR 与远程桌面缩放都可能改变结果。
- 无额外缩放时，可用 `物理尺寸 mm = 控件像素 ÷ 有效显示区像素 × 有效显示区物理尺寸 mm` 估算。若通过 PPI 换算，需先确认所用 PPI 与实际显示映射一致。
- 字号取决于观看距离、字体字面、汉字笔画、现场光线和视力差异。字体数字相同不代表可读性相同；在目标面板查看正常、选中、禁用、报警和低质量数据状态。
- 触控需要同时验证热区大小、可见边界、相邻目标间距和触屏定位误差。允许热区大于图形，但不得重叠到无法预测命中哪个控件。
- 对戴手套、湿手、振动环境按实际使用条件测试；不要只用设计电脑上的鼠标点击通过验收。
- 按下反馈应立即可见；动作是否执行以控制系统回执/反馈为准。界面动画不能冒充设备已动作。
- 新设计的可点击按钮必须有 `s0` 常态和 `s1` 反馈态，按下时有实际可辨的外观变化。瞬时按钮松开/取消后恢复；导航和切换的保持选中规则另定义。标签、画布与锚点一致，不能只改文件名或等设备回执才给按下反馈。
- 记录测试设备、光照/距离、手套、任务、误触/漏触与辨识结果，再调整候选 token。测试条件改变后重新评估。

## 3. 页面层级与导航

采用“全局概览 → 区域/单元 → 设备详情 → 诊断/维护”的层级作为候选结构，按设备规模合并或拆分，不强制固定层数。页面必须围绕操作任务组织。

- 概览回答“哪里需要关注、整体是否正常、下一步去哪里”；详情回答“当前对象发生了什么、能做什么”。
- 持续显示当前设备/工位、当前页面、运行模式、关键通信状态与必要报警入口。关键状态不得只藏在弹窗中。
- 导航位置和返回语义跨页一致；切到另一对象时明确更新对象标题、位号和操作目标，避免误操作旧对象。
- 常用监控、报警、趋势、参数、维护入口按任务排序。维修和管理功能受权限约束；不要让操作员通过多层无关菜单寻找异常。
- 为页面列出主要任务和关键判断。内容过多时按任务分组或拆页；不得靠无限缩小字体塞满。
- 确认弹窗应完整显示目标与后果。不可让遮挡后的画面、过期值或后台选中对象成为唯一依据。
- 弹窗关闭、权限到期、网络恢复、浏览器返回后的页面行为要确定，避免动作无意重发。

## 4. 布局、字号与数据表达

- 用栅格和对齐建立稳定阅读路径；按“对象/设备”“实时数据”“操作”“诊断”分区。相同类型控件使用相同内边距、尺寸、状态与标签方式。
- 栅格是对齐工具，不应压过真实的工艺连接关系。流程图需要能看清流向、支路、设备位号和可点对象；装饰管道不得遮挡数值或连接关系。
- 主数据、操作标签、页面标题与辅助文字形成有限层级。辅助文字可以弱化，但不牺牲操作条件、单位、失败原因的可读性。
- 数据采用稳定数字布局，优先验证等宽数字；刷新时避免因位数变化导致标签、单位或其他控件跳动。
- 每个值明确名称/位号、单位、所代表的量与质量状态。区分设定值、实际值、目标值、累计值、瞬时值和限值。
- 小数位与仪表分辨率、测量质量、操作决策相匹配。禁止用多余小数制造精确感；有效精度由项目确认。
- 同类量保持单位与格式一致。单位切换后同时转换范围、步长、阈值和历史轴标签；不可只换单位文字。
- 区分 `0`、无数据、不适用、无效、超量程和数据陈旧。无效值不默认为零；需要显示最后有效值时，明确标记其时间与质量。
- 超范围、溢出、负值、长设备名、中文/英文、最大日期长度都要纳入版面检查。关键单位与正负号不得被截断。
- 时间需要明确来源、时区/本地时间约定和格式。跨站点、夏令时或历史回放可能影响判断时，显示必要的时区与时间范围。

## 5. 颜色、对比度与图形语义

颜色以项目批准的报警、设备状态和现场标识策略为准。先建立“语义 → 文本 → 图标/形状 → 色彩 → 状态行为”的映射，再设计调色板。不能把“运行必为绿”“故障与急停都用同一种红”当作跨设备通用规则。

- 正常状态采用能稳定阅读的视觉表现；用有限的高显著性元素表达真正需要关注的信息。浅色或深色主题由现场验证决定，不按行业标签预设。
- 每个关键状态至少有文字或可辨识图形冗余，颜色不能成为唯一信息通道。例如“离线”文字配断链图标，而不是只把所有值变灰。
- 避免同一颜色兼指设备运行、可操作按钮、图表曲线和报警优先级而无上下文区分。保留报警语义色的辨识度。
- 图标需要在目标尺寸、灰度与色觉差异条件下检查。纯图标操作若易混淆，应加短标签；不得依赖生图生成的模糊符号。
- 动画仅用于真实流向/变化或项目批准的状态提示；不使用持续装饰闪烁。报警是否闪烁、何时停止由报警策略明确，不能自行编造节奏。
- Web 界面可将普通文字对比度 4.5:1、关键控件与图形对比度 3:1 作为候选检查值；具体阈值与适用条件按界面要求确定。覆盖文字大小、状态、背景和叠层检查，不能用数值检查替代面板现场实测。
- 实际检验要覆盖不同状态与背景、半透明叠层、图像上的文字；不能只测主色和白底这一组。

## 6. 状态模型与组件状态

设备状态、连接质量、操作权限和命令状态是不同维度，不能用一个“绿色/灰色灯”概括。每个可控组件应有状态表；不适用项写明原因。

| 状态/维度 | 需要表达的内容 | 操作规则 |
| --- | --- | --- |
| 运行 | 来源于设备实际反馈的状态；必要时含模式/阶段 | 显示当前允许的操作及条件 |
| 停止 | 已收到停止反馈；与启动中、停止中分开 | 不等于已隔离能量或允许检修 |
| 故障/报警 | 对象、问题、优先级、时间和建议响应入口 | 依项目许可决定是否禁用动作，不能仅凭 UI 推断联锁 |
| 离线/通信失败 | 失联对象、最后更新时间与通信质量 | 标明值不可作为当前事实；控制按设备定义的失联策略处理 |
| 数据陈旧 | 通信可能还在，但某项数据超出项目允许的新鲜度 | 标明“陈旧”和最后有效时间，不冒充实时值 |
| 无效/未知 | 未初始化、质量位无效、超量程等具体原因 | 不回填为零或默认正常；提供诊断入口 |
| 权限不足/只读 | 当前身份、缺少的权限或可用的授权入口 | 不显示成故障；禁用或隐藏策略跨页一致 |
| 条件不满足 | 联锁、模式、设备占用、流程条件等已知原因 | 可见解释与下一步，不只提供灰按钮 |
| 触控按下/焦点 | 当前命中目标、键盘焦点或选中对象 | 视觉反馈清晰，与“设备运行”图区分 |
| 待确认 | 用户尚未确认目标、参数与后果 | 明确确认/取消；取消不发送命令 |
| 已发送/等待回执 | 命令已提交，正在等待接收/执行反馈 | 限制重复提交；显示等待状态和时间信息 |
| 执行成功 | 接收成功与实际执行成功按平台能力分别表示 | 不因按钮被点击就提前显示成功 |
| 拒绝/失败/超时 | 控制器拒绝、校验失败、通信超时等原因 | 给出可理解的原因；不自动重试有副作用命令 |
| 结果未知 | 请求可能已到达，但回执丢失或超时无法确定 | 提示核对设备实际状态后再操作，避免盲目再次启动 |

操作反馈的超时值、数据陈旧阈值、按钮锁定策略与恢复方式由项目给定，不能统一写死为某个秒数。状态显示与后台控制策略应有可追溯的数据字段或事件对应关系。

## 7. 报警与事件

- 报警列表服务于响应：让操作员知道发生在哪里、严重性/优先级、何时发生、是否仍活动、是否已确认、建议去哪里排查。报警优先级来自项目报警策略，不由 UI 作者按视觉喜好排序。
- 活动/已恢复、未确认/已确认分别显示。**确认报警不等于故障解除、设备复位或恢复运行**；确认动作的含义应写入操作说明。
- 消音、确认、复位、搁置、抑制是不同动作，只呈现平台与项目支持的动作，并明确权限、范围和后果。
- 如支持搁置/抑制，需可见状态、原因、适用时限与恢复入口；不能把仍然存在的问题做成“正常”状态。
- 复位前说明对象与前置条件；复位被拒绝时展示原因。复位是否可能导致后续动作由设备方确认，不预设复位必然安全或自动重启。
- 排序、过滤、搜索与暂停滚动行为应明确；过滤生效时保留醒目标记与复原入口。避免新报警到来使当前待点击行跳到另一个对象。
- 区分报警、提示、操作事件与维护记录，不把所有消息做成同一优先级的红色通知。
- 可从报警进入相关设备/趋势/处置说明，并保留返回上下文。批量确认应明确当前范围；不通过“一键清空”隐藏仍活动的报警。


## 8. 参数、输入与有后果的操作

- 参数编辑区显示当前有效值、待提交值、单位、允许范围、步长/精度与生效方式。范围和权限需在实际控制/服务端校验，界面限制不能代替校验。
- 区分“输入中”“尚未保存”“已提交”“已应用”。离开页面时处理未提交内容；保存失败保留用户可恢复的输入，并指明哪项未生效。
- 软键盘不能遮住当前字段、单位、限制和提交结果。考虑负数、小数点、本地小数格式、前导零、粘贴异常字符与字段长度。
- 多参数提交明确是否原子生效。若仅部分成功，逐项标识真实结果，不能只弹出一个“保存成功”。
- 高后果操作按项目风险与操作规程选择机制，如明确目标/后果的二次确认、权限验证、模式/联锁检查或专用流程。不要为所有普通点击增加确认，也不把“长按”当作通用安全保证。
- 启动、停止、模式切换、配方下载、批量写入等动作需明确作用对象、影响范围和反馈来源。危险操作与频繁导航/普通编辑应有足够空间与视觉区分。
- “取消”通常只能取消尚未发送的请求。请求已经到达控制器后若支持中止，应提供有明确语义的中止流程；不能仅关闭弹窗就暗示设备动作已撤销。
- **屏幕中的软件停止按钮不等于安全急停，也不替代安全回路、实体急停或能量隔离程序。** 未经专门安全设计与验证，不将普通触控按钮命名为“安全急停”或画成可替代安全装置的承诺。
- 展示“急停已触发”等反馈时，数据必须来自项目定义的真实信号，并标识信号质量。操作 UI 与安全功能职责由设备/安全负责人界定。

## 9. 趋势与历史

- 每条曲线标明变量、单位、图例与质量；时间轴明确实时/历史、起止范围、时区与是否暂停。
- 自动缩放、固定量程、双轴需要明确规则。不同单位不要共用一个未说明的轴；告警限值与目标线有清晰标签。
- 无效或丢失数据显示断点/质量标记，不插值成未发生的稳定运行。历史聚合/抽样可能掩盖峰值时，说明其处理方式。
- 光标读数、区间比较与放大缩小提供可返回的复位入口；触屏交互必须与戴手套条件匹配，不能只依赖精细鼠标悬停。
- 实时趋势暂停后持续显示“已暂停”和暂停时间，不让静止曲线伪装成稳定的当前过程。

## 10. 多分辨率与平台落地

| 已知约束 | 推荐选择 | 必须验证 |
| --- | --- | --- |
| 固定低分辨率厂商面板 | 按原生分辨率设计专用布局，优先原生数值/报警/输入控件 | 实机字体、位图边缘、触区、刷新与内存 |
| 同比例多尺寸面板 | 评估逻辑布局复用，逐设备验证物理尺寸；必要时分档 | 不能仅按整屏比例缩小触区与文字 |
| 不同比例屏幕 | 重排分区、定义锚点或提供专用版面 | 关键操作/报警不裁切，不出现不可达区域 |
| Web HMI/桌面 | 明确断点、缩放、键盘焦点和浏览器支持 | DPR、系统缩放、可访问名称、焦点与输入 |
| 图形能力有限的平台 | 用可支持的控件/位图层实现，减少重阴影、模糊、透明叠加 | 色深、字体回退、状态贴图、资源预算与性能 |
| 不支持 SVG/复杂透明度 | 提供已验证格式与必要的背景适配导出 | 抗锯齿、透明边、压缩色差与状态一致性 |

- 不默认所有面板支持现代 CSS、可变字体、矢量动画或高频全屏刷新。先用最小样例验证平台能力，再扩展整套画面。
- 背景和装饰可切片，动态数值、报警文字、单位与关键按钮标签优先使用平台可更新的文字/控件。确需栅格文字时记录语言、缩放和维护限制。
- 给实现方交付组件状态、坐标/尺寸、可点热区、数据绑定、交互和失效行为；单张效果图不足以说明交互。
- 不以“响应式”一词代替具体决策。交付每种目标分辨率/比例下的布局规则与实际截图或预览。

## 11. 评审完成条件

每个项目至少保留以下可审查材料：

- 约束表、页面清单、任务流程与假设/待确认项。
- 项目 token、组件规范、语义色映射、状态矩阵及其数据来源。
- 正常、故障、离线、陈旧、无权限、命令等待、失败/结果未知的代表画面。
- 实机或等效条件的可读性与触控记录；多分辨率溢出、语言扩展与平台资源验证结果。
- 从效果图到控件/切片的实现说明，以及允许的视觉降级。
- 需要设备/工艺/安全负责人确认的逻辑与参数清单。没有证据的项目保持“待确认”，不得为了通过评审改成“已验证”。

## 12. 页面族、组件分层与方向性操作

多页面产线界面按 [页面框架与组件设计方法](page-framework.md) 组织公共区域与业务内容；位置、颜色和尺寸按设备与任务确定。

- **先做公共外框，再做内容模板**：明确状态栏、报警区、业务内容区和导航的职责、矩形及固定/可变关系。某页没有报警时，约定保留空间还是重排，不能由每个页面临时决定。框架稿中的空内容区可以是有意预留，需标注完成阶段。
- **导航选择与业务状态分开**：导航表示当前模块或页面，当前位置保持可辨识；导航选中态不能覆盖或伪装成设备运行状态。导航位置按设备与任务选择，不强制放在底部。
- **以组件家族维护一致性**：按钮底板、图标、可编辑标签、命中区和设备反馈分别定义。组件家族记录尺寸变体、构成层、字体字重、状态和组合规则；底板未带文字不代表切图缺字。图标或灯的像素边界不等于操作热区。
- **品牌入口与运行页分工**：登录/启动页可采用品牌插画；长时间监控页采用更稳定的阅读背景与信息层级，主题由现场条件确定。不要把登录页的装饰密度扩展到所有运行页面。
- **方向性写操作显示源→目标**：参数读取、配方下发、导入/导出等操作，应写明数据对象、源、目标、作用范围和是否覆盖。不能只用“上传/下载”或上下箭头让人猜方向。可使用“读取 PLC → HMI”“下发 HMI 配方 → PLC”等当前工程认可的文案，并定义请求、接收与生效反馈。长按时长和权限机制由当前工程确定。
- **跨区核对同一状态**：顶栏摘要、报警条、设备卡和详情页若说法不同，检查来源、对象范围、时间与质量。确属不同维度时明确标签；尚未解释的冲突不能作为可接受正常状态示例。
