# 渲染性能与 GPU 选择

需要选择实际渲染后端时运行 `python scripts/probe_render_environment.py --out 项目目录/render-environment.json --reuse`；纯规范、局部文字评审不先探测硬件。工具在同机、同解释器且6小时内复用报告，`--refresh`强制新探测；过期/刷新写新报告并返回report_path，不覆盖旧证据。只读收集CPU、内存、显卡/驱动及可见工具，检测失败记录unknown并使用可用后端。缓存不自动发现驱动变化，环境改变须刷新；每次检查同一已知Python/Node路径，不反复寻找或安装。

1. HTML/CSS/SVG 页面合成、大量场景、WebGL/3D、动画预览优先使用已有浏览器/渲染器的 GPU 加速路径；不默认加 `--disable-gpu`。有集成显卡也可用，不要求必须 NVIDIA/CUDA。
2. 查询实际后端（浏览器 GPU 状态、WebGL renderer、渲染器设备报告等）；系统列出显卡只能证明硬件/驱动可见，不能证明本次绘制用了 GPU。SwiftShader、llvmpipe、WARP 等软件后端按 CPU 回退记录。
3. PNG 少量裁切/编码、字体测量、CSV/JSON、哈希和数据库操作通常保留 CPU。不要因为要求 GPU 优先而搬运小任务，造成更大启动/传输耗时。
4. 根据分辨率、素材数量、显存/内存和代表任务耗时设并发；先复用同一渲染会话及组件源，避免每图启动一个浏览器。只有具有代表性的对照证明加速有效时，才报告加速倍数。
5. GPU 不可用或输出异常时换可用后端，记录原因、选择和实测；不为普通设计任务擅自安装驱动、更改系统全局显卡配置或关闭其他程序。

性能探测不渲染生产 PNG，也不绕过流程1/流程2/流程3的设计确认。1:1 独立组件输出不因 GPU 模式改变画布、字体、锚点或目标像素。


正式组件导出优先使用 [export-validation.md](export-validation.md) 的复用浏览器入口。记录探测、浏览器启动、逐组件渲染、内容/重组检查、规格导出与打包时间；对话等待另计。缓存键至少含源/样式/字体/尺寸/状态和后端，不以“文件已存在”跳过内容检查。浏览器私有配置保留在系统临时目录并记录，不进入交付；按 [追加式生成](generation-lifecycle.md) 分配新批次，生成结束不递归清理缓存或历史。
