# 自动验收

完整 UI 设计交付后自动检查实际产物并生成报告，不要求用户逐个文件检查。自动检查的范围、执行环境和未完成项必须分开记录；文件或模拟逻辑通过不能直接写成真实浏览器验收通过。

## 自动执行范围

方向打样阶段运行 [方案库构建与检查](style-library.md) 中的 `check_style_logic.cjs`；完整交付阶段运行下述验收。两者阶段不同，不能因方向样例的其他页面尚未展开而假装完整工程通过。

| 层级 | 自动检查内容 | 能证明什么 |
|---|---|---|
| 目录与清单 | 必备文件、相对路径、清单哈希、字节数、遗漏与重复、ZIP逐文件一致 | 文件交付完整且可追踪 |
| 页面与资产 | PNG真实尺寸、透明信息、画板倍率、图层边界、组件归属与状态组 | 几何和资源契约一致 |
| 按钮双态 | s0/s1齐备、相同画布、解码RGBA像素不同、逻辑尺寸匹配 | 双态没有缺片或同图改名 |
| 标注数据 | HTML嵌入数据与结构化规格相同、资源使用相对路径 | 标注和交付数据未漂移 |
| 功能原型契约 | 1.1变量类型/范围/步长、绑定、导航目标、显式行为、required_features覆盖 | 已提供当前要求的原型结构；旧1.0标注包记为missing_annotation_only |
| 纯逻辑单元检查 | 运行维护模板的可信事件函数，检查标注、画面内s0/s1、瞬时复位、IO切换、输出强制/解除、切页、参数有效/无效/取消、仪表棒图及演示时钟清理 | 交互处理逻辑在模拟条件下符合预期 |

按钮像素不同不保证差异足够醒目；相同画布不保证锚点准确。字体、颜色、真实点击命中、指针捕获、CSS排版和下载行为仍需浏览器验证，现场可读性与设备执行仍需目标环境验证。

## 执行

构建交付目录及 ZIP 后运行：

```powershell
python .\scripts\accept_delivery.py --package .\exports\hmi-ui-delivery --node node
```

默认范围为 `complete`。报告写在交付目录之外，避免改变已打包内容；已有报告保留，新报告使用序号或显式新路径。

只对明确限定的文件和逻辑层做自动检查时，可使用：

```powershell
python .\scripts\accept_delivery.py --package .\exports\hmi-ui-delivery --node node --scope files-and-logic
```

`--node` 指向可用的 Node.js；检查使用标准库和纯代码测试，不依赖网页、服务器或浏览器。Python 需要 3.12+ 与 Pillow。依赖不可用时标记受阻，不擅自安装或把未执行写为通过。

`scripts/check_viewer_logic.cjs` 只接受与维护模板行为脚本一致的交付 HTML，再用测试替身检查已知逻辑。它不执行任意交付脚本，不渲染页面、不接入浏览器，也不读取或改变任何真实 UI 状态。

## 状态与完成条件

- `pass`：仅表示所声明范围的检查实际通过。
- `fail`：文件、数据或处理逻辑不符合契约，列出对象和原因后修复重跑。
- `blocked`：必要能力或正式访问权限不可用，保持未完成；禁止用其他通道绕过明确的访问限制。
- `not_checked`：没有执行相应检查，不计为通过。
- `not_applicable`：该项不适用于当前交付，写明原因。

退出码：限定范围通过为 `0`；自动检查失败为 `1`；完整范围仍有受阻环节为 `3`。命令参数错误遵循解析器的错误退出约定。

当前离线检查程序没有浏览器执行能力，因此 `complete` 范围在文件与逻辑通过后仍会保留浏览器受阻状态；`files-and-logic` 的通过也不能用于宣称完整界面验收完成。需要完整验收时，必须另行获得正式允许的浏览器入口并保存真实操作、画面和结果证据；不可仅通过参数改写成通过。

报告中的 `prototype_delivery=provided` 表示1.1功能原型数据存在；`missing_annotation_only`表示旧包只有标注。该字段需结合文件契约与逻辑检查结果阅读，不能单凭字段存在宣称交互合格。旧包的限定文件检查通过不豁免当前完整交付的HTML原型要求。

对自动检查实际失败的项目，修正后重跑受影响检查；访问受阻时记录具体条件，不无限重试，不自动扩权。
