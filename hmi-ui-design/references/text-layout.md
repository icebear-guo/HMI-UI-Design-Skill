# 统一字体测量与尺寸适配

V2.11 test2对静态文字、数值显示、数值输入使用同一个`assets/editor-kit/text_layout.py`。新项目通过`build_project.py`自动调用；不再由各模型重写“中文一字宽、英文0.58字宽”等估算。主题、行业、设备、业务内容及素材仍可自由设计。

## 字体与坐标

测量Windows GDI实际加载的字体、负像素高度和字重，核实字体名称与所需字形。缺字体、字形或测量能力时报告具体控件并停止相关构建/复制，不静默替换字体或回退估算。尺寸采用画布逻辑像素，不按Windows缩放百分比乘除字号。浏览器缩放、屏幕分辨率、应用DPI和MCGS画面缩放分别记录。

已标定的是有限样本：McgsPro3.5.1.6963、微软雅黑常规/粗体、主要字号12/14/16/18/24/28，短文字另有13；Windows2560×1600、缩放200%。其他字体/字号仍可实测，但报告保留原厂显示待验，不能冒用这次样本结论。按钮/导航的内嵌文字等其他控件没有自动继承本轮原厂标定。

## 两种余量候选

默认`mcgs351-c`：GDI文字宽+16、高+8；紧凑选项`mcgs351-b`：宽+8、高+4。这是原厂对照样本可用的候选余量，不是MCGS内部固定边距，也不是已证明的最小尺寸。整数坐标按中心取整，最多半个设计像素偏差。

项目源可设置`text_layout:{"profile":"mcgs351-b"}`；组件可用相同字段覆盖。默认采用C，不必填写。局部编辑面板对应“文字边距：充足/紧凑”。修改字体、文字、小数位或范围后点击应用，重新测量并按需要扩框；不自动缩字。切为紧凑不会主动缩小既有尺寸，需要时可同时调整宽高。

## 数值与边界

以声明上下界、初值、小数位和正负号计算宽度；再用各数字字形的保守宽度包络覆盖中间值比端点更宽的情况。包络字符串仅用于测量，可能超出业务范围，绝不写入变量初值、绑定或脚本。当前格式是十进制、固定小数位、不带分组分隔符；其他显示格式另行实现与验证。

新同源项目的数值范围来自全局变量。旧模型未给显示范围时只能检查初值，报告保留宽度覆盖未完成；不能据此宣称所有运行数值均不会裁切。数值显示的范围仅用于预留文字宽度，不会生成原厂限幅逻辑；数值输入上下限继续写入输入控件。

数值输入复制检查从两个真实原生字段回读固定小数位，而非只复述网页请求值。标定中出现过自然小数使-888888.75显示为-888889的情况，应先核对格式，不能一律按裁字或DPI问题处理。

## 扩框与空间不足

构建和局部应用保留控件中心、字体及业务字段，只扩大不足的尺寸。新增与邻近控件的重叠、超出原承载底图或画布会报告控件ID并停止该次生成/应用。助手应调整源布局/留出空间，不能通过删字、改静态图或缩字号凑过检查。原有文字框重叠单独列警告，不能将检查通过解释为所有布局语义正确。

构建输出`text-layout.json`，列出原框、新框、所需尺寸、样本文本、数值宽度包络、碰撞和标定范围。源项目声明尺寸与构建模型最终尺寸可能不同，预览和原生都必须读取构建后的同一模型；重建使用相同源与工具版本。不得另写HTML继续使用旧尺寸。

原生复制前再次使用同一测量函数检查实际当前模型。编辑器没有隐式修改任意HTML；复杂自定义预览仍须使用同源最终矩形。

已有模型可单独运行：

```powershell
python scripts/layout_text.py --model 项目/model.json --policy check --report 项目/text-check.json
python scripts/layout_text.py --model 项目/model.json --policy grow --out 项目/model-fitted.json --report 项目/text-fit.json
```

使用新输出文件，不覆盖源。失败只输出报告，不写不可用模型。旧模型适配完若要用于复制，应以新模型建立新会话；旧网页及旧运行代码不会自动升级。

## 验证顺序与证据

本轮126组对照完成文字及数值的有限样本显示验证，不代表任意字符串、真实上下界、其他DPI或其他版本均已验。接入后的自动测量、模型回环和浏览器检查属于工具验证，不能替代新页面在MCGS中的显示、组态、编译、重开和真实业务行为。先用一页实际布局回归，再按实际需求扩大，不固定要求客户重复全套矩阵。
