# HMI UI 质量检查

检查范围与交付深度相匹配。规范文件检查不能代替实际图像检查，图像检查不能代替工程导入及设备测试。

## 设计与状态

- 页面主任务明确，总览能定位异常，详情能追踪到设备、数据和操作。
- 简短需求已有助手提出并纳入C1确认的 [内容计划](../assets/page-content-plan.template.md)，所选配方已按实际设备改写；C2使用同一内容对比布局色调，C3各页有对应任务模块，未靠空框、无关装饰或同稿换标题填页。
- 布局、色值、字号和间距符合本次项目参数；偏离项有具体原因。
- 文字、数值、单位、精度、阈值与数据来源分开说明，未给出的工程参数没有编造。
- 超长文本、最大/最小值、负数、离线、失效数据、权限不足和命令失败有定义；通信未知时不误显示正常或运行。
- 报警含可识别文本、优先级、时间/来源和处理状态，颜色有冗余表达；确认与故障恢复分开。
- 触区按实际物理屏幕和使用方式检查；没有把模板中的候选像素值当成人体工学合格证明。
- 高影响操作的触发、权限、反馈和失败恢复来自工程要求；画面没有把软件停止包装成安全急停。
- 多页公共外框与内容区边界一致，导航、当前页面和操作对象明确；标清框架稿、内容样例、交互稿或已实现工程，不能把留白框架当成全部功能已实现。
- 顶栏、报警带、卡片、详情的状态若不一致，核对对象范围、数据源、时间与质量，或明确不同维度，不能默许相互矛盾的“正常/报警”。
- 读写/配方传输明确源→目标、对象与覆盖范围；仅有上下箭头、上传/下载文字或历史长按时长，不能证明操作语义与反馈完整。

## 图像与切片

- 依据C3已确认的HTML逐页盘点全部可见图形与必要状态，按 [元素覆盖规则](asset-coverage.md) 对照最终文件。人形/装饰/导航/警告/通信图标、独立小灯与IO LED、设备状态灯、设备图、按钮子层、背景/面板/弹窗等均在范围内；不能只检查已经导出的文件。
- 图形默认有独立PNG，可编辑矢量母版能提供时另附。原生实现、仅交矢量或静态背景合并例外有逐项可复现规格/父资产映射及客户明确确认；没有把“CSS/SVG能画”“可替换图标库”当作自动豁免。动态指示灯未合入静态背景。
- 共享资产的每页实例均有映射，组件底板、图标和指示子层分开核对。没有把整条状态栏笼统标为原生，遗漏其中图标与灯；文字、实时数值和趋势采样按原生绑定规格处理，不要求逐字或逐采样点出PNG。
- 所有元素已导出或具备有效客户确认例外；缺项、缺态、未决或悬空引用标为fail/blocked，不宣称完整交付通过。自动文件覆盖检查之外，已人工逐页对照HTML，核对盘点自身未漏录。
- 实际打开交付文件检查画布、清晰度、边缘、裁切区域与错误内容；不能只检查扩展名或提示词。
- 真实像素尺寸与清单一致；原图哈希、裁切矩形、状态命名和输出版本可追踪。
- 画板逻辑尺寸、预览导出倍率与独立资产像素分别核对；没有从2x截图继承错误字号/热区，也没有对已有切片再次盲目除以2。
- 透明件确有透明像素；若需要半透明边缘，还检查 alpha 过渡。深/浅底预览没有明显底色、白边或阴影截断。
- 同一状态组的画布、锚点和设备位置一致，没有通过不同裁框造成切换跳动。
- 每个新设计按钮均有 `s0/s1` 两态，实际图像有可辨的交互差异；按下、松开、取消及需要保持选中的规则已定义。缺态、同图改名、位置跳动或将点击直接显示为执行成功均需修正。
- 历史状态编号有工程映射证据；未确认的 `s0/s1` 保持未映射。底板、图标、文字与热区组合关系明确，文字未被遗漏或重复烘焙。
- 字体/图标/商标来源与使用范围已记录；竞品分析素材与己方可发布资产能够区分。
- 目标平台实际支持导出格式和资源大小；未实际导入时检查状态写“未验证”，不能写“可直接上机”。

## 离线交付包

- 完整UI项目已按 [客户确认清单](project-workflow.md) 记录C1参数、C2实际样例HTML、C3规定数量全套交互HTML的有效客户确认；没有把偏好回答、自检通过或旧版认可当作当前确认。
- 三项未全部确认前以HTML评审，未提前渲染PNG或切片。修改后提供最新HTML并重交受影响阶段，不通过“渲染管线验证”绕过流程。

- HTML 不依赖网络脚本、字体服务或外部图片；从交付目录直接打开时页面、资产和标注可用。
- 完整UI交付须有画面内可操作的HTML原型。按 [功能原型](interactive-preview.md) 验收适用组件；只有静态稿、标注热区或属性区按钮演示属于交付缺口。
- 瞬时按钮取消/失焦/切页后复位；IO文字与灯态一致；输出模拟强制能解除；导航切换实际内容；参数可输入、校验、确认/取消；仪表棒图同值联动并可重置。底板切换不丢字，不露出旧读数。
- 页面导航、缩放、图层命中和属性显示正确；坐标/尺寸使用设计单位，与预览倍率区分。
- 页面预览、独立资产、字体文件与清单逐项对应；缺少可分发字体时明确说明，不能用空文件冒充。
- 压缩包与目录内容相符，解压后层级和相对路径可用；没有将原始资料、训练记录、缓存或无关文件混入。
- 构建成功只表示文件打包完成。记录实际做过的浏览器检查与尚未测试的环境，不把结构校验写成完整交互验收。

## 问题等级

| 等级 | 判定与处理 |
|---|---|
| 阻断 | 误导设备/报警状态、伪造参数、关键操作歧义、切片越界或不可导入；修正后才交付对应生产资产 |
| 主要 | 关键数据难读、状态缺失、触区未核实、图像结构错误；交付草案时突出说明并给出下一步 |
| 次要 | 非关键对齐、轻微视觉不一致；集中修正或记录可接受偏差 |

评审报告写“位置 → 观察事实 → 对操作/交付的影响 → 可执行改法”，不要只写“更高级”“不够工业”。

## 检查结果记录

区分 `pass`、`fail`、`not_checked`、`not_applicable`。记录文件/页面、检查动作、观察结果与证据路径。脚本通过只证明其覆盖的机械检查通过，不能代替视觉、交互和现场验收。尚未做的事情不得使用“全通过”“已上机”等结论。

完整交付按 [自动验收](automatic-acceptance.md) 生成报告；必要能力受阻时另标 `blocked`。纯逻辑测试使用替身对象，不能将其操作结果描述为真实浏览器点击、排版或视觉检查。
