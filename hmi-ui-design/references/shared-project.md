# 同一项目源驱动预览、编辑与原生复制

MCGS项目按**复用模板资产 → 一份项目源 → 代表页验证 → 展开全套**制作。先按[需求引导](design-intake.md)确定行业/设备用途和任务，复用匹配的原生结构、独立素材和主题，在一份`hmi-ui-project/1.0`项目源中组织业务与布局。调用现有12类工厂生成可编辑、可复制的实际HTML会话，预览和复制读取同一模型。该会话就是主交付入口，不先写完整业务HTML再重建“原生版”。

这不是任意HTML/JavaScript到MCGS的转换器。自定义HTML的渲染器读取同一源构建后的最终模型，文字、变量、资产和几何不再另存一套业务定义；尤其要使用字体适配后的矩形。超出工厂能力的效果/逻辑逐项登记。用户提供的已有独立HTML可按其授权迁移，但不能声称天然可复制。只改已有模型时，沿用原局部入口即可。

## 一条制作路径、一个交付入口

1. 从用户需求先列页面任务和必需内容，记录能复用的模板/资产及修改项；清单不从已生成控件反推。
2. 在同一源中制作代表页，使用下方构建命令直接建立带变量定义、模拟初值和原生控件类型的可编辑/复制会话。数据接口在此指设计变量与已支持绑定字段，不表示已连接PLC或具备真实工程身份。
3. 助手先在该会话检查内容、字体、局部编辑和原生生成；已有方向评审继续使用这个入口，不另外要求用户审批“原生版”。
4. 在同一源展开已约定页面并重建会话。用户查看、局部修改及复制始终从当前会话进行，修正也回到源组件及其依赖。

模板`hmi-ui-editor-model/2.0-test`与项目源schema不同。已有模板模型可直接作为权威模型建立编辑会话；若迁移到项目源，按类型整理变量引用、资产引用、页面和需求映射，不能改后缀充当转换，或在转换后继续独立维护旧模板业务内容。纯素材与明确仅做效果稿的任务按其实际范围处理。

这条路径消除两套交付页面的重复维护和常规逐项对比；仍检查当前模型的边界、内容覆盖、浏览器操作和原生结构。检查的是同一个交付成果，不重新生产一套用于比对的页面。

## 项目源

`assets/project-source.example.json`是三页结构验证示例，不是客户默认行业、默认页数或固定外观。复制到项目目录，按实际需求修改：

| 字段 | 用途 |
|---|---|
| `context` | 行业/应用场景、设备用途、操作任务与假设；先整理已有信息，不重复问已知项 |
| `canvas` / `font` | 实际像素画布和默认文字样式；原生路径支持七种尺寸，见[分辨率适配](resolution-adaptation.md)，当前批次1～6页 |
| `variables` | 全项目设计变量：`name/kind/initial`；数值再给`min/max`及可选`digits`。初值必须在范围内 |
| `assets` | 命名独立资产，`svg`、项目内`svg_file`或`image_file`（PNG/JPEG）；图标、设备母版均可新增 |
| `pages` | 实际页ID、名称及组件；坐标仍为`[left,top,right,bottom]`，不固定分区和模板 |
| `requirements` | 从需求/内容计划独立登记的预期内容，再映射到页面组件；不能反过来只列已生成对象来凑完整 |

组件沿用[12类字段](local-editor.md)，以`variable:"字段名"`引用全局变量。`svg:"@资产ID"`及状态中的`@资产ID`复用素材。数值专属背景写`skin:"@资产ID"`，编译为该数值控件的内置图片槽，不额外叠底图。公共卡片、设备、图标仍独立。

一份变量定义在各页使用相同设计身份与初值；首次切页只补尚不存在的变量，保留共享值。项目变更会生成新源哈希和页面版本，不把旧草稿自动套到变化后的源。网页局部编辑仍记录补丁，复制使用应用后的当前模型；需要把改动纳入可重建项目时，将相关补丁回写到对应源组件，再生成新批次。

```powershell
python scripts/build_project.py --source 项目/project.json --out 项目/build-r1 --port 18780 --allow-copy
```

输出包括源快照、`pages.json`、`coverage.json`、会话、项目内运行代码及`open-editor.cmd`。双击该启动器，或直接运行`runtime/scripts/start_editor.py --session session/session.json`。复制已被用户要求时可用`--allow-copy`，无需再询问；默认未绑定，名称模式可用`--binding-mode names`保留原选项。

V2.11 test2同时输出`text-layout.json`，按[统一字体测量](text-layout.md)扩展不足的文字/数值框；预览和原生读取扩框后的相同矩形。扩框碰撞、越界或缺字体时停止建立可复制会话，保留报告，由助手调整布局后生成新批次。不能另写一套HTML继续使用源声明的旧小框，也不能把停止报告当作交付。

布局、主题、SVG图形、母版和组件组合可自定义。图标可使用独立图片控件；缺专用图标类型不是删图理由。不能将不同动态字段画成静态文字或把整页压成背景来绕过缺型。

## 内容覆盖

每项requirement有`id/page_id/role/component_ids`。`reading/parameter/command/indicator`再给预期`variable`。角色包括静态文字/底图`static`、图形`graphic`、读数`reading`、参数`parameter`、命令`command`、灯`indicator`、导航`navigation`、报警条`alarm_strip`、实时/历史报警`alarm_realtime/alarm_history`与组合对象`object`。

例如14个已约定参数应独立列14项；手动对象逐对象列任务/必要控件；历史报警要映射实际history浏览。工具会报告缺对象、错类型、错变量、实时代历史、孤立组件和源版本漂移。工具检查声明过的清单，不能证明清单本身没有漏需求；仍须与客户内容计划核对。

能力未实现时保留该项，写`status:"deferred"`、具体`reason`及空`component_ids`。报告为partial；这允许继续查看/复制已实现内容，但不能将该项目说成全部完成。映射错误为fail，新构建保留报告并停止生成不完整模型。

```powershell
python scripts/check_project_coverage.py --source 项目/project.json --pages 项目/build-r1/pages.json --out 项目/coverage-check-r1.json
```

退出码：完整映射0、缺型未完成3、缺失/错误1。覆盖检查不审批预览复制，不要求先正式切图。

## 通用本地交互

编辑器复用`preview_runtime.js`实现完整数值解析、范围/精度校验、瞬时按钮释放与SVG实例ID隔离。瞬时按钮处理鼠标、键盘、移出、取消、失焦、隐藏、切页和进入编辑模式；不能再在click中重置按下量。数值输入缓冲使用完整数值；合法千分位可解析，部分数字、错分组、超精度均拒绝，不静默截取或舍入。

数值共享通过同一`variable`自动联动。简单演示还可在命令/输入上声明`preview`：`requires:{变量:值}`，以及`on_press/on_release/on_toggle/on_commit`下的赋值；赋值可以是同类型常量或`{"from":"变量名"}`。条件只控制本地演示，未知真实阈值/联锁不得凭空补成工程定义。

**这些演示条件与联动不会变成MCGS脚本或PLC逻辑。** 原生按钮仍只有已支持的按1松0/取反；效果项会在覆盖/构建报告和页面提示中标明待外部实现。未绑定控件可后设变量，静态label则没有自动变动态的能力，两者必须分开。

## 浏览器与原厂分别检查

```powershell
node scripts/check_editor_browser.cjs --url http://127.0.0.1:18780/ --out 项目/browser-r1.json --channel msedge --native-check
```

使用已有Playwright；缺依赖报告blocked，不自动安装。可通过`NODE_PATH`或`--playwright-module`指向当前环境已有模块。工具检查真实浏览器文字（含数值声明上下界）、组件ID、切页变量、瞬时释放与可选原生结构；不发布剪贴板。它不认证任意业务逻辑、现场可读性或MCGS运行，复杂状态变化另列项目案例。失败退出1，运行能力缺失3；报告必须对应当前源/会话。

代表页先覆盖实际内容、编辑及复制路径，再批量展开其余页面；这复用原有方向评审，不增加固定审批轮次。用户明确委托按实际范围记录，不能从“没要求评审”推断授权。当前原生字段、窗口保护/绑定/导航等未验分支继续如实保留待原厂验证状态。
