# 参数引导与首次方向打样

适用：首次完整UI设计，或需要重新确定视觉方向的大幅改版。先复用已有输入，再补缺项，完成同页HTML候选，让用户选择方向后展开其余页面。局部修改、单项素材、规范评审以及已有明确设计系统的任务，按指定范围执行，不额外设置选型环节。

## 先读取，再提问

先读取用户消息、需求文件、现有工程和已确认参数，用 [需求记录](../assets/project-brief.template.md) 标出已知、待确认、暂定。已有分辨率、导航偏好或配色要求不重复追问；发现冲突时只问冲突项。不要将模板中的候选值当成用户输入。

优先补齐以下内容：

| 参数 | 需要区分的内容 | 缺失时如何推进 |
|---|---|---|
| 目标画布 | 原生宽×高像素、横/竖屏、应用缩放；屏幕对角英寸及有效物理宽高另记 | 可用明确标注的暂定画布先打样；最终切片尺寸与触区结论必须核实 |
| 使用平台 | 面板/工程软件与版本、触控/手套/鼠标键盘、字体与图像支持 | 草案使用本地模拟，不虚构设备能力或工程绑定 |
| 页面内容 | 本轮页面范围、导航项目及数量、代表页的设备/数据/操作内容 | 先整理一个能体现关键任务的代表页，模拟数据需显式标识 |
| 导航布局 | 底部、侧边、顶部或待建议；位置是否已有固定要求 | 提供合理候选；不要擅自将项目项数当成固定模板数量 |
| 视觉方向 | 浅色、深色、两者比较或待建议；强调色、已有品牌与样式约束 | 未定时纳入打样比较，已确定的要求在各候选中保持一致 |
| 现场条件 | 观看距离、昼夜/强光、安装环境及关键角色 | 保持假设标识，现场可读性与触控验证单独记录 |

“尺寸”不能只记为“10寸屏”：物理大小决定可读性和触控判断，像素分辨率决定画布与导出，两项均需分别记录。

## 让用户容易回答

一次优先问最影响设计的2～3组缺项，按当前缺口裁剪问题。提供少量选项，并允许回答“不确定，先建议”；不要求用户先填完整份工程表。可采用以下问法：

1. **屏幕与平台**：“屏幕原生分辨率是多少，横屏还是竖屏？若知道，也请提供屏幕英寸和工程软件；不确定可先写设备型号。”
2. **页面与导航**：“先做哪个代表页面？导航放底部、侧边，还是由我比较建议？有哪些导航项目，约多少项？”
3. **色调与现场**：“偏浅色、深色，还是两种都看？有必须沿用的颜色/风格吗？主要在明亮还是较暗环境使用？”

平台、输入方式或关键页面内容仍缺失时，在后续轮次补问。能从资料核实的内容直接记录。用户允许先建议时，说明暂定内容并完成可比较的HTML，避免反复停在提问。未经回答不能把假设标记为已确认。

## 同一代表页先出可选择的HTML

方向未定时，默认制作3个有意义的候选；用户可指定数量。所有候选使用同一代表页、相同文字、变量、模拟数据、状态与画布，差异集中在布局和色调，便于比较。布局变化应实际改变导航位置、内容分区、信息密度或主次关系，不能只改主题颜色后声称存在多种布局。

- 从 [可扩展方案库](style-library.md) 选择或新增布局与主题，记录各自ID和版本。不得为了凑数量违反用户已经明确的导航位置、背景色或其他约束。
- 例如在允许范围内比较“浅色+底部导航”“深色+侧边导航”“浅色+重点数据分区”；若导航已固定，改比较内容分区与信息密度。
- 每个候选提供实际HTML画面和简短差异说明；标出画布、导航、主题和暂定参数。提供统一比较入口，不只给提示词、配色表或几张截图。
- 至少用代表性组件演示按钮s0/s1、可编辑参数或数值联动。仅用于方向比较的HTML明确标为方向打样，不冒充全部功能、切片和工程交付均已完成。
- 先完成文件、资源、画布及可执行范围内的交互检查，再请用户选择；浏览器受阻时如实标记，不能把纯逻辑检查写成真实浏览器通过。

候选记录使用 [方向打样模板](../assets/style-proposal.template.json)。阶段成果是可评审的样例，不在此时提前批量完成尚未定向的全部页面。

## 选择、混选与后续展开

提供具体入口后，再以一句明确的问题请求选择，例如：“请选择A/B/C，也可以选A的布局+B的配色，并说明需要调整的地方。”这是用户要求的首次设计流程；只约束依赖视觉方向的后续批量页面，不扩展为所有任务的通用审批要求。

用户可直接选择一个候选，也可混合指定布局与主题。混选后生成组合后的代表页并呈现实际结果；若组合影响内容区尺寸或可读性，修正后再确认最终方向。记录variant ID、layout/theme ID与版本、打样输入哈希、画布版本、用户明确选择及尚未解决的调整项。

未收到选择时保持 `awaiting_selection`，不能将等待时间、默认高亮或工具检查通过当成用户认可。可继续完善数据规格、公共组件规则和修复样例等不依赖方向的工作；选型前不擅自批量制作其余页面。用户已明确指定方案、确认既有设计系统或要求直接按其方向继续时，记录依据并跳过重复打样。

方向确定后，将选中的主题和布局合并为本次项目参数的单一版本，再展开页面、资产与交互。后续修改先更新该项目参数，再应用到相关页面；通用方案库保留独立版本，避免一次项目调整无意改变其他任务。
