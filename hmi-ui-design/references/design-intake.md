# 需求引导：行业、设备、内容，再到视觉

用于新HMI设计或大幅改版。目标是帮助客户把设备需求变成具体画面和可复用组件，而不是让客户填完长表或只能选预置外观。已有资料先读，已知项不重问；局部编辑/既有页面复制按相关范围执行。

仅调用技能、没有设备信息或用户明确表示不会使用时，先走[弹窗全程引导](beginner-guidance.md)：同轮收集屏幕尺寸/分辨率、行业设备、先看总览候选或直接制作5/6页。下文是助手整理设备内容的参考，不是首轮弹窗之外还需逐项问完的长问卷。

## 开始时先说明路径

简要说明：先用弹窗确认屏幕、行业设备及本轮范围。选择先看方案时制作运行总览布局/色调候选，看过实际HTML后弹窗选择或修改，风格确定后选5/6页或自定义；选择直接整套则沿用首轮范围制作，不重复问页数。HTML出现后即可编辑和复制到MCGS，正式通用素材另按需输出。

首轮按三类信息使用实际交互提问工具，已有答案直接沿用，只补缺项。后续必要工艺问题也优先集中弹窗，用设备用途表达，允许“不确定，先建议”；不要在没有实际HTML前展开冗长工程问卷。

屏幕题按[四个常用组合](beginner-guidance.md)提供英寸＋分辨率快捷选择，同时可自填其他规格或型号。选中后直接沿用组合，不重复问分辨率；仅知道英寸或实际型号参数不同时，以用户实际资料为准。

## 首轮之后：按预览需要整理设备内容

按已有信息补问，行业和设备优先于配色：

1. **行业与用途**：用在哪个行业/场景？具体是什么设备，主要完成什么工序？不知道行业分类时说设备用途即可。例如水处理、包装、温控、输送等只是帮助描述的例子，可自由填写，不是封闭选项。
2. **工艺与任务**：有哪些主要设备/工位，它们如何配合？操作者最常看什么、调什么、控制什么？可参考已有照片、工艺图、旧界面或文字说明；暂时没有也可先描述。
3. **本轮范围**：只做一张画面还是一套页面？已有页名、必要功能或目标分辨率可一起提供；没有页面清单就由助手据任务提出建议。

首轮弹窗的完整字段和分支以[弹窗全程引导](beginner-guidance.md)为准。这里的工艺/任务信息优先从已有材料提取；只有会改变设备示意或使预览无法成立时才继续补问，否则先以标明的示意内容制作HTML。

用户只给“1024×600”或“做几张好看的界面”，还不足以生成项目主画面。此时先补设备用途，不先展示三个通用主界面让其选色。用户主动只要主题样板/纯控件测试，可直接做相应样板，标明没有行业业务内容，不把它当完整项目。

## 第二轮：整理内容，再补必要约束

读 [内容配方](content-library.md)，由助手拟“设备/工艺对象 → 操作任务 → 页面模块 → 数据、状态与动作”。不让客户从零写逐页策划。未知阈值、联锁、信号和数据标为模拟或待核实，不猜真实地址。

用 [需求记录](../assets/project-brief.template.md) 的项目副本汇总，按本轮需要补下列信息；前面已有回答不重问。

| 信息 | 记录内容 |
|---|---|
| 行业与设备 | 行业/场景、设备名称/用途、主要工序、对象及连接关系，来源/假设 |
| 操作者任务 | 常用监控与操作、关键异常、模式/权限与命令反馈；不用装饰指标凑数 |
| 页面计划 | 本轮页数、ID/名称、用途、必要模块、导航清单和代表页理由；数量按任务建议 |
| 画布与平台 | 原生宽×高px、方向、软件/版本；屏幕英寸与物理宽高另记，不能只写“10寸” |
| 操作与现场 | 手指/手套/鼠标、距离、明暗、字体/图像支持；只问会影响本轮设计的项 |
| 视觉与既有资产 | 品牌、已有风格/资产、设备图表现、导航倾向和色调偏好；未定可让助手建议 |
| 输出 | HTML编辑/原生复制、可选通用素材；不提供MCGS兼容素材或离线MCP写入选项 |

默认品牌“工控北极熊（抖音）”，无需单独追问，用户指定优先。性能探测按 [render-performance.md](render-performance.md) 在需要选择渲染后端时执行，不替代需求引导。

## 内容与素材复用计划

在参数汇总/内容计划中加入复用说明，不增加固定审批轮次：

- 本项目的设备/工艺关系；需要独立表达的设备、零件与端口。纯IO/参数项目可无设备插画，不强制添加装饰设备。
- 现有模板、设备母版、公共组件、图标及12类原生结构中，哪些直接复用，哪些改参数/外观，哪些新增；记录源ID/版本及匹配理由。
- 设备图形风格和业务关系独立：按 [设备图鉴](equipment-atlas.md) 先关系、再独立母版、再实例组合；旧泵/罐不能冒充不相符的行业设备。
- 复用以结构/端口/角色/风格是否匹配为依据，不能只看行业名字相同。新增素材保留可编辑源、稳定ID、状态和实例映射，便于以后再用。
- 布局和色调可以重新组合、新增；页面内容不为迁就三套模板而缩水。原生未支持项提前列出，保留通用设计源，不宣称动态能力已经实现。

页面内容写入 [内容计划](../assets/page-content-plan.template.md) 的项目副本。展示带版本的精简汇总：行业/设备、关键任务、建议页数/内容、复用与新增项、已知/暂定项，再按本次授权请客户确认或记录明确委托。没有设备依据也没有自选示例授权时，先补关键问题；用户说“你来设计”通常可覆盖布局策划，不自动表示可以替他猜行业。

## 代表页HTML：再选布局与色调

首轮选择“先看方案”时，默认用本项目运行总览制作左侧导航、底部导航两种实际布局，并提供四种色调独立选择，实际可访问后再弹窗询问采用的组合/修改。公共框架及大小屏内容容量按[默认布局规则](default-layout-rules.md)执行。用户明确要求其他代表页或范围时按其指定。直接整套分支可自主工具核对代表页后继续全部页面，不插入未要求的客户审批。记录[主题/布局](style-library.md)的ID/版本，也允许新增方案。

候选使用同一画布、内容、数据和状态。差异可在导航、内容分区、信息密度、设备图组织和色调，不能只换色就称为多种布局。至少演示适用的按钮反馈、数值/输入或关键联动；不用整页PNG包装成交互HTML。客户可混选或自定义，呈现组合后的实际版本再确认。

“选蓝色”是偏好；只有对最新实际HTML的明确反馈才能记录为该版本的人工确认。生成文件、默认高亮、下载选择、工具通过均不代替客户确认。用户已明确委托的阶段按delegated记录真实授权，不伪填确认。

## 全套页面与两条输出

按约定范围展开页面和交互，公共框架复用，各页保留自身任务。提供当前逐页入口、ID/名称、实际与预期页数、检查结果，按 [交互预览](interactive-preview.md) 实现适用行为。视觉评审与文件/浏览器/原厂验证分别记录。

HTML预览阶段即可选择、编辑、复制控件或完整窗口。只有复制所选图形/皮肤时即时渲染必要图片，不等待全套页面或正式切图，也不顺带生产整批未选素材。

用户需要正式通用素材包时，在对应设计范围确认或有效委托后，按 [项目流程](project-workflow.md) 输出。仅请求HTML/原生复制可到此交付，不强制走正式切图。设计阶段用可编辑HTML/CSS/SVG，已有位图可只读复用；复制即时所需图片与最终素材生产分开记录。

使用 [流程记录](../assets/project-workflow.template.json) 记录parameters、direction、interactive_ui的实际版本/文件及确认或委托依据；局部任务标实际范围。参数/页数/视觉/交互变化只使受影响的下游依据失效，保留旧版和不受影响成果。沉默或等待时间不算同意，明确指向当前成果的回复按上下文解释。
