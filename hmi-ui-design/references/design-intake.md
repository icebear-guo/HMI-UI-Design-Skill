# 参数引导与客户确认

**默认品牌（1.05）**：用户未指定公司/品牌名，直接使用“工控北极熊（抖音）”展示于设计预览，不为此追问。指定名称优先，原始已确认稿不擅自改品牌。开工先只读探测性能并按 [render-performance.md](render-performance.md) 选后端。

适用完整HMI UI设计或大幅改版。项目开始先向客户说明 [项目流程清单](project-workflow.md)：**流程1初始参数确认 → 流程2最新样例HTML确认布局与色调 → 流程3规定数量的全套交互HTML确认 → 正式切片与最终输出**。三个确认均由客户完成，按顺序记录；助手负责整理、制作、检查和修订，不能代替客户确认。

规范评审、单项素材或明确局部任务按实际范围执行，记录不适用阶段及原因，不把局部成果称作完整UI交付。完整设计即使已有规范、指定了颜色或导航位置，也必须提交至少一版代表页HTML供流程2确认。

## 开始时告知客户

在收集参数时说明本轮范围、阶段成果及等待客户确认的位置，可使用以下说明：

> 本项目先确认初始参数；随后我会生成代表页HTML，请你确认布局和色调；确定后再制作约定数量的完整UI HTML，演示适用交互并请你逐页确认。三项全部确认后，才开始正式切片和最终文件输出。你可以在各阶段提出修改，修改后的当前版本需要重新确认。

用 [需求记录](../assets/project-brief.template.md) 汇总输入，并用 [流程记录模板](../assets/project-workflow.template.json) 记录阶段、实际文件版本和客户确认依据。首次回复即让客户知道哪些事项需要其确认，不在已经开始切图后才补充流程。

## 流程1：读取、补缺项，再确认参数

先读取用户消息、需求文件、现有工程及已确认参数，标出已知、待确认和暂定。已有内容不重复追问；发现冲突时只问冲突项。模板数值不是用户输入。

| 参数 | 需要记录与确认的内容 |
|---|---|
| 目标画布 | 原生宽×高像素、横/竖屏、应用缩放；屏幕对角英寸及有效物理宽高另记 |
| 平台与操作 | 面板/工程软件与版本、手指/手套/鼠标键盘、角色、字体与图像支持 |
| 页面范围 | 明确总页数、每页ID与名称、用途、必要内容、导航项目清单与数量；指出代表页 |
| 导航布局 | 底部、侧边、顶部或先比较建议；项目名称、顺序及固定要求 |
| 视觉偏好 | 浅色、深色、两者比较或先建议；强调色、已有视觉约束 |
| 功能范围 | 各页需要的按钮、IO、参数输入、导航、仪表、棒图等交互；本地模拟与真实工程绑定分开 |
| 语言与交付 | 页面语言、需交付的HTML、切片、预览、资源及格式要求 |
| 现场与未知项 | 观看距离、明暗/强光、安装环境；允许暂定项、限制及最终必须核实的内容 |

“尺寸”不能只记为“10寸屏”：物理尺寸用于可读性和触控判断，像素分辨率用于画布与导出，分别记录。

尺寸/分辨率只限定画布，不足以决定业务内容。缺少逐页描述时，读取 [内容配方](content-library.md) 和适用的 [状态组件](state-components.md)，由助手先拟 [内容计划](../assets/page-content-plan.template.md)：每页的任务、核心/可选模块、字段/单位、质量状态和适用交互。客户已有内容优先；未知数据标模拟或待核实，不能默认为真实工程定义。页面数量未知时先建议清单，不擅自开工六页。

一次优先询问最影响当前阶段的2～3组缺项，允许“不确定，先建议”，不要求客户先填完长表。按缺口采用以下问法：

1. **屏幕与平台**：“原生分辨率是多少，横屏还是竖屏？若知道，请提供屏幕英寸、工程软件和操作方式；不确定可先给设备型号。”
2. **设备任务与页面**：“设备大致做什么，日常主要监控或操作什么？本轮只做主画面，还是一套页面？若没准备内容清单，我先建议各页模块供你确认；已有页名可直接给我。导航放底部、侧边、顶部，还是先比较建议？”
3. **色调与现场**：“偏浅色、深色，还是两种都看？有必须沿用的颜色/风格吗？主要在明亮还是较暗环境使用？”

补齐后展示带版本的参数汇总，列出总页数、各页内容计划、已知项和暂定项，再请客户确认流程1。客户允许“先建议”时，先把建议参数和模块写入汇总并获得其明确认可，才生成依赖这些参数的样例HTML。未确认期间可继续查资料、整理规格或修复通用工具，不开始依赖流程1的页面生产。

## 流程2：提交最新样例HTML，再确认布局与色调

本阶段和流程3均以实际HTML评审，不提前渲染PNG或切片。用原生HTML/CSS/内联SVG表达布局、文字与双态；只读引用已有客户位图不等于可以新增PNG渲染。不要交一张PNG包在HTML里充当新的交互样例。

流程1确认后，方向未定时默认制作3个有意义的候选，数量可按客户要求调整。已有明确偏好或规范时，按约束至少制作一版代表页HTML。所有候选使用同一代表页、相同文字、变量、模拟数据、状态及画布，差异集中在实际布局与色调。

- 从 [方案库](style-library.md) 选择或新增主题/布局，记录ID和版本；不为凑数量违反已确认的要求。
- 使用流程1已确认的代表页内容计划，体现对象/状态、任务数据、适用操作和异常表达；不能只用空白卡片或通用假指标代替本项目内容。各候选内容一致，布局可重排，不能靠删减模块让某方案显得更整洁。
- 布局变化应实际改变导航位置、内容分区、信息密度或主次关系，不能只换色后称为多种布局。导航位置已固定时，可比较内容组织方式。
- 提供可打开的当前HTML入口、版本及差异说明，使用 [打样清单](../assets/style-proposal.template.json)。至少演示按钮s0/s1、参数或数值联动等代表性交互；此时是方向样例，不是全部功能交付。
- 完成文件、资源、画布及可执行范围内的交互检查，再请求客户确认；浏览器受阻时如实标明，纯逻辑通过不能冒充真实浏览器验收。
- 客户可选整套，也可混选布局与配色。混选后先生成组合后的最新代表页，呈现实际结果，再确认这个版本，不能只记录口头组合。

**回答“暖灰浅色＋左侧导航”只提供了偏好；没有查看并确认对应最新HTML时，流程2仍未完成。**提供具体文件入口后，询问客户是否确认该版本的布局与色调、允许据此展开约定页面，并记录其明确回复。生成文件、默认高亮、下载选择记录或工具检查通过，都不能自动将状态改为客户已确认。

## 流程3：规定数量的全套交互HTML，再确认完整UI

流程2确认后，使用已确认主题、布局及项目参数制作流程1约定数量的UI HTML。提供逐页入口、page ID/名称、当前版本、实际页数与预期页数对照，以及各页适用功能的检查结果。

画面内实现适用交互：按钮按下s1、松开/取消复位；灯与IO点击切换；模拟输出强制与解除；导航切换实际页面内容；参数输入/校验/确认/取消；仪表和棒图联动。不能只交静态截图、标注热区或按钮属性区演示。细则见 [交互原型](interactive-preview.md)。

先呈现完整UI HTML当前版本，再请客户确认页面数量、逐页内容、布局色调一致性及交互表现。流程2只确认代表页方向，不能替代流程3对全套页面的确认。阶段内使用可编辑组件、矢量或CSS状态制作评审稿，不能以“验证渲染管线”为由提前批量制作正式切片。

## 全部确认后再切片与最终输出

检查流程1、流程2、流程3均已由客户明确确认，且对应当前文件/参数版本、页面清单与实际数量一致后，才进入正式切图、独立PNG切片、生产预览、资源清单和最终交付压缩包。具体条件以 [项目流程清单](project-workflow.md) 为准。

方向打样HTML和全套交互HTML属于必须先交付客户评审的阶段成果，可以在确认前提供；它们不等于已获准进行最终资产输出。

每次记录客户原话或消息位置、确认时间、对象、版本及实际文件，不能编造确认记录。未回复保持待客户确认，不以等待时间、含糊的“继续”或工具成功推定通过；必要时只澄清确认对象。

参数、布局色调、页数或页面交互有变化时，更新版本，重交受影响阶段确认，并使相关下游确认失效。已确认旧版不能批准新版；只有不受改动影响的独立事项可继续。相关最新版本重新确认后，再恢复依赖工作。
