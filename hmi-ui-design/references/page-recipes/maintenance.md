# 系统维护内容配方

ID：maintenance；版本：1.0.0；状态：建议。只加入本项目需要的诊断和维护内容。

**主要任务**：判断系统/连接状态、识别待维护项目，并找到适用的维护或诊断入口。

| 优先级 | 内容模块 | 内容与表达建议 |
|---|---|---|
| 核心 | 系统/设备信息 | 设备对象、软件/界面版本、运行时长等有依据的信息 |
| 核心 | 连接诊断 | 控制器/设备连接、最后更新时间、质量与已知异常原因 |
| 按任务 | 维护项目 | 项目名称、累计/剩余周期、到期状态、检查记录；未知周期不虚构标准值 |
| 按任务 | 会话与权限 | 当前用户/角色、可用维护操作、登录/退出入口 |
| 可选 | 事件与辅助 | 诊断记录、时间配置、资源/备份信息，仅展示范围内真实可实现的内容 |

**布局建议**：按系统信息、诊断和维护任务分区；待处理项优先，版本等辅助字段不占据整个工作区。操作入口应说明对象和结果，避免无上下文“清空”“恢复全部”。

**HTML样例**：选择诊断对象查看实际对应的模拟详情，切换质量场景与公共通信状态联动；选中的维护项显示其记录。若演示复位计数或配置变更，区分修改、取消和模拟生效。未实现备份、身份认证或系统写入时明确范围，不显示伪成功。

**内容检查**：维护页面提供可理解的系统状态与任务，不能只陈列版本号，也不能添加无需求依据的高影响操作。
