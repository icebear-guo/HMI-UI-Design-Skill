# 页面框架与组件设计方法

适用：多页产线界面、公共页面框架、组件家族、设计标注和切片交付。

本规范围绕操作任务组织页面，将公共外框、业务内容、组件和工程状态分别定义。量化演示见 [布局示例](../assets/layout-example.json)；示例用于说明布局与倍率，实际参数按设备和现场条件校准。

## 页面框架

| 区域 | 设计职责 | 一致性要求 |
|---|---|---|
| 全局状态栏 | 时间、对象、身份、模式、连接和必要状态 | 跨页位置与含义稳定，显示当前对象和数据质量 |
| 报警区 | 需要处理的异常、时间、对象与入口 | 没有报警时明确是否保留空间，不临时遮挡关键操作 |
| 业务内容区 | 监控、参数、工位、趋势、报警明细等任务 | 使用内容模板，避免每页重新定义公共结构 |
| 导航 | 业务模块和页面之间切换 | 位置、顺序和当前页面表达一致 |

先约定区域的矩形、固定/可变关系和隐藏规则，再制作具体页面。导航可以位于底部、侧边或其他合适位置，不强制固定数量。登录/启动页可集中视觉表达，长期监控页优先保证稳定的阅读结构。

框架稿需明确标为框架，内容样例、交互设计与已实现工程分别记录；空内容区不代表所有功能已经完成。

业务内容从 [页面配方](content-library.md) 选择并实例化为项目内容计划，不仅预留一个“中央主工作区”。公共外框跨页固定；总览分栏、参数列表、报警表、IO网格等内部组织按任务改变，不要求所有页面复用同一套指标卡。适用组件及状态参见 [组件使用参考](state-components.md)。

## 组件家族与分层

组件按家族维护尺寸变体、构成层、字体层级、状态、锚点和命中区域。

- 背景与容器负责分区，避免烘焙实时数据与交互文字。
- 按钮底板、图标、可编辑标签、触控热区分别定义组合关系。
- 输入框区分展示、编辑、待提交、失败和只读状态。
- 指示灯与设备图只表达已定义的反馈，图形大小不自动成为触控要求。
- 同组状态保持相同画布、锚点和基线；已有合格独立资产优先复用，避免从整页预览重复截取。

分层同时决定最终交付范围：从已确认HTML逐页登记全部可见图形及必要状态，包含底板、图标、指示灯、装饰和设备图等子层。每个图层/实例具有稳定ID并映射到资产或获客户确认的交付例外；共享资源可复用，但实例不可漏记。顶栏的人形、通信图标和小状态灯应各自登记，不能被一条“顶部原生内容”覆盖。具体范围与完整性条件见 [元素覆盖规则](asset-coverage.md)。

图形默认独立PNG，可编辑矢量母版另附。采用原生实现或静态背景合并时，提供可复现规格或父资产关系并取得客户确认；CSS/SVG绘制方式本身不构成省略依据。动态灯态不能藏在静态背景中。文字、实时数值与趋势数据保持可编辑/可绑定，不将每个字或采样点制成位图。

这些盘点和分层关系可在C3 HTML评审中确定；C1/C2/C3全部确认之前，不为完善资产清单而提前渲染PNG或切图。

精确几何组件由同一可编辑源导出，生图用于适合的背景或设备素材。文字和状态变化不依靠逐片生图猜测。

完整设计还需将这些分层组件实现为 [可交互HTML原型](interactive-preview.md)：底板双态与标签分别渲染，IO/参数/仪表/棒图绑定显式本地变量，导航切换实际页面内容。组件图层不能只停留在静态标注。

## 逻辑坐标与导出倍率

分别记录设计画板、实际预览和独立导出文件的尺寸。

例如：设计画板为 1024×600，预览为 2048×1200，且没有裁边或原点偏移，则 `sx=sy=2`。设计矩形 `[24,540,124,40]` 对应预览裁框 `[48,1080,248,80]`。

独立按钮若已按 1×导出为 124×40，应直接使用其真实像素，不再次除以 2。不同导出物可以采用不同倍率，不能由查看器缩放、全局配置或文件名猜测。换算规则、取整、阴影留白和原点偏移需单独记录。

示例中的字号、按钮尺寸和颜色均不代表现场合格值。图形尺寸、可读性与热区分别按实际屏幕和操作方式验证。

## 状态映射

新设计的每个可点击按钮必须具备 `s0/s1` 两态，不能只交一张常态图。

| 状态 | 视觉与触发要求 | 结束条件 |
|---|---|---|
| `s0` 常态 | 清晰表达按钮可点击；保持可读标签 | 接受按下输入后进入 `s1` |
| `s1` 反馈态 | 填充、边框、图标明暗或凹陷效果有明确变化，让操作员能看出输入已命中 | 瞬时按钮松开、移出取消或输入中断后回到 `s0` |

导航/切换按钮若以 `s1` 表示持续选中或开启，组件规格须明确保持与复位条件；需要同时表达按下与选中时增加独立状态，不复用一个状态掩盖区别。禁用、等待回执、失败等表现按功能另补，不能因此省略基本双态。

两态保持相同画布、尺寸、锚点、留白与文字位置，避免切换跳动；视觉差异要在实际显示尺寸上可辨，不仅有文件名不同。点击反馈即时发生，不等 PLC 回执才显示；设备执行、成功、失败和结果未知依真实反馈另行表示。

导入既有状态资产时，记录原编号、所属维度、语义、触发条件、绑定/反馈依据及核实状态；缺少依据时保留 `unmapped`。这不改变新设计按钮的双状态要求。

按下、选中、运行、故障、权限不足、离线和数据陈旧属于不同维度，不能使用同一编号关系推断。相同画布只证明外框尺寸一致，仍需检查图标锚点、内容和工程反馈。

## 数据方向与结果反馈

参数读取、配方下发、导入/导出需要说明对象、源→目标、覆盖范围及生效条件。可按实际工程使用“读取参数：控制器 → 操作面板”“下发配方：操作面板 → 控制器”等明确文案；箭头和上下传词汇作为辅助。

请求已发、对端接收、实际生效分别表示。失败、超时和结果未知不能提前显示成功；权限、确认机制、重试和恢复由实际工程定义。

## 标注与跨区一致性

- 共享组件的名称和对象 ID 可能复用，定位时结合画板、图层和实例。
- 母版 `name` 不等于实例 `content`；读取真正显示内容并核对画面。
- 顶栏摘要、报警区、设备卡和详情若说法不同，检查对象范围、数据源、时间和质量，明确不同维度。
- 对齐基线和间距使用明确参数，修正非预期微差，避免把单个图层的偏移扩散到组件家族。
