# 追加式生成：保留历史，避免反复删除

**1.06补充**：新目录不等于重新计算全部内容。按[incremental-generation.md](incremental-generation.md)同步变化草稿、复用校验合格的资产；旧输入的渲染器兼容模式不自动提供增量，必须实际接入静态缓存配置。不得仅因保留历史就宣称已经实现增量生产。

适用于评审HTML、组件PNG、切图、规格和交付包的生成与重试。批次目录变化不改变项目设计revision：确认关系仍绑定实际源内容，不能靠换目录跳过确认或验收。

## 默认执行方法

1. 首次运行或重试均分配新的批次目录，例如 `review/ui-<batch>`、`render/assets-<batch>`、`exports/delivery-<batch>`。不在构建脚本里执行 `rmtree`、`Remove-Item -Recurse`、`rm -rf` 或逐文件删除旧输出后重建。也不以整目录搬走历史来规避删除保护。
2. **已存在则换新批次**，禁止“目录已存在→删除→重试”。源HTML/CSS等未冻结草稿可以正常局部修改；新评审/输出引用其实际版本。已确认快照、已交付包和失败证据不覆盖。
3. 项目生成脚本（包含其自写的辅助脚本）先保存为文件，运行前静态预检；修改脚本后重检。不把删除代码塞进未检的临时命令或动态脚本。预检只查传入文件的已知模式，不执行脚本，也不是完整安全沙箱；不得把它的pass称为没有任何删除风险。
4. 新批次失败时保留已写文件和失败报告，标记fail/partial；下次分配新目录。不得把半成品ZIP、只生成部分PNG或无成功报告的目录当交付。只复用内容哈希与参数一致、重新验证合格的资产。
5. 最终包按清单只收当前成功批次；不打入历史批次、失败目录、浏览器缓存或私有配置。需要“当前版”入口时仅更新一个小的入口/索引文件并记录目标，不清空整个输出根目录。

## 工具入口

以下命令以技能目录为当前目录；`PROJECT`表示本次项目目录，需替换为实际路径。

```powershell
python scripts/check_generation_policy.py PROJECT/build.py PROJECT/build_helpers.py
python scripts/new_generation.py --root PROJECT/render --prefix assets --check PROJECT/build.py --check PROJECT/build_helpers.py
```

分配器返回 `generation_dir`、`component_source_dir`、`manifest`、`render_out`、`delivery_out`，并在新目录内写 `generation.json`。把源组件及manifest放在该批次内；渲染/交付目标仅返回路径，不预建，供现有工具独占创建。新建批次不等于资产或MCGS规格已验收。新脚本有删除命中时分配器在创建目录前拒绝。

`check_generation_policy.py`支持Python AST及JavaScript/PowerShell/shell常见删除模式；动态别名、间接调用、依赖和宿主自身行为不保证覆盖，不整库扫描。直接人工制作、没有项目生成脚本时可省略`--check`；不能把此例外用于隐藏已存在的构建脚本。

已发布的组件渲染器每批复用一个浏览器并关闭自己的会话；本批私有配置保留在系统临时目录，报告记录其路径。打包/方向包保留自己的工作暂存目录，成功后它通常为空；失败时保留部分输出、可能不完整的ZIP和独占创建的`.generation-failure-*.json`。切图写盘失败同样保留已写文件，不逐个删除回滚。磁盘写满或强制终止可能无法写出失败报告，缺少明确成功证据仍不得交付。

## 清理与宿主提示

确需释放空间时，把清理列为独立任务：先列明确切目录、内容和体积，再在用户授权范围内按宿主正常审批操作。生成流程不自动清理历史、缓存或失败批次，不拆小删除数量、改阈值或隐藏命令来绕过保护。

宿主可能累计本会话早先操作的删除数量；其他工具也可能删除文件。本规则消除UI生成链自身的常规批量删除，不能承诺宿主永不提示。已触发的提示不会因更换skill自动撤销；先核实待执行内容，再按宿主流程处理。
