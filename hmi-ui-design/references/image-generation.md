# HMI 生图规则

## 选择生成内容

适合生图：设备示意插画、结构示意的视觉底稿、材质或背景探索、独立设备资产、风格参考。设备结构、管线、方向等会影响理解时，必须对照工程资料核验；生成结果不是工程图纸。

适合原生绘制：可编辑标签与中文、实时数值、输入框、按钮、报警与趋势、精确图标、品牌已有矢量资产、要求像素准确的布局。风格探索图可展示整体方向，但要另行构建工程组件和交互。

用户要求“生图”时，用当前环境可用且符合要求的图像生成工具实际生成；只要求“提示词”时才只交付提示词。若环境提供 `image_gen`，按其当前工具契约调用。生成新图不附带无关参考；编辑图像前查看用户指定的目标图，再按工具支持的引用方式提供它。用户已经要求生成时，通常无需再次确认。工具不可用则明确说明，交付提示词和可实现的布局部分，不编造文件、下载地址或生成完成记录。

## 生成前锁定

使用 [提示词模板](../assets/image-prompt.template.md)，从实际项目参数直接填入以下项目：

- 用途与边界：参考稿、背景还是可导出独立素材；哪些内容由工程控件覆盖。
- 目标画布与比例：实际交付像素、构图比例、安全边距、主体占比；区分“希望模型输出的尺寸”与“实际取得的文件尺寸”。
- 主体：设备部件、数量、结构、朝向、视角、光照、材质与需要保留的识别特征。
- 统一风格：同组资产的投影、透视、描边和光源；色值引用项目参数，不写无依据的“工业蓝”。
- 背景：需要透明时明确请求工具生成真正的 alpha 透明背景。不要用棋盘格或纯白底代替透明。
- 状态：默认、按下、禁用、报警等各状态保持相同画布、锚点与构图。若只需改色或轮廓，优先从同一可编辑源构建状态，避免多次生图造成结构跳变。
- 避免项：不可读文字、虚构商标、额外设备、复杂装饰、与工程结构冲突的连线、文字压在关键资产上。

不要要求生成模型为精确字号、网格、工程尺寸提供保证。生成结果要测量，布局、文字与绑定在可编辑层中实现。若工具只支持近似比例，先获得接近目标的构图，再采用可追溯的布局或派生处理；不得拉伸设备以强行凑尺寸。

## 按资产组织生成

已有页面模板和组件家族时，先确认“公共外框/内容/组件底板/图标/可编辑文字”的分工。登录或启动背景可用生图探索视觉方向；监控页的固定导航、标签和状态组件沿用确定的设计参数。按钮、输入框、指示灯等几何家族优先由同一可编辑源导出变体，不逐片生图猜尺寸。组件分层与组合见 [页面框架与组件设计方法](page-framework.md)。

新设计按钮的最终资产必须有 `s0` 常态与 `s1` 反馈态。即便先以生图探索风格，也要从统一母版制作双态，保证尺寸、文字、结构和锚点一致，并在实际显示尺寸检查按下变化；不能交一张图后声称工程会自动补出另一态。

1. 同一组只改变本次需要改变的变量。先确定一张基准样式，后续使用可用参考图能力保持结构、视角、材质和光源一致。
2. 要独立设备或图标时优先单资产或明确分组画布，预留切片边界与投影。不要依赖一次生成的复杂界面自动得到完整可用切片。
3. 已有合法源资产能直接复用时优先复用；对原图修改，保留母版和派生关系。竞品图只分析信息组织和交互模式，不提取其 logo、独特视觉作为己方品牌资产。
4. 输出原图后检查：设备结构、边缘、透明通道、画布实际尺寸、同组状态是否偏移、关键细节有无遗漏；以像素事实修正交付说明。
5. 若出现结构错误，先定位是哪项约束失败，再有针对性修订提示词或更换制作方式。连续两次修订仍不能满足同一关键约束时，交付已验证部分和具体限制，提出矢量/原生绘制方案；不无限重试、不假装通过。

## 生成记录

每组记录用途、工具/模型（工具未暴露的项写“未提供”）、时间、完整提示词、引用资产路径/标识、实际输出路径与尺寸、alpha 是否真实存在、参数版本、发现的问题和派生操作。只有工具确实返回 seed 等参数时才记录其值；“相同提示词”不等于可复现相同像素。

本轮仅制定生图规范时，无需为说明规则而额外消耗生图额度。真正生图后的检查按 [质量检查](quality-review.md) 和 [切片交付](slicing-delivery.md) 执行。
