# 项目流程、需求引导与预览即时复制

## 每个环节都帮助用户操作

新手和无需求启动见[全程引导](beginner-guidance.md)。本文件的阶段名和证据字段由助手维护，不要求用户理解或填写。每次提供当前实际成果/可用入口，再用简短步骤说明如何查看、修改或复制；用户只需描述设备、反馈实际效果和完成必要的原厂操作。不得把一段长提示词当作使用前置，也不把“引导”变成固定审批关卡。

## 新项目的设计顺序

新设计/大幅改版先读[弹窗全程引导](beginner-guidance.md)、[需求引导](design-intake.md)和[内容配方](content-library.md)。起步弹窗收集屏幕尺寸/分辨率、行业设备、先看总览候选还是直接做整套。行业设备明确后，用实际设备内容生成HTML，不用空泛模板或长工艺问卷代替预览。

先看方案分支：实际总览候选HTML→弹窗选布局/色调、混搭或修改→采用当前实际版本后弹窗选5页/6页/自定义→展开整套。直接整套分支：沿用首轮范围，先做必要工具核对再生成全部HTML，不重复询问页数或添加未要求的风格审批。

通用设备默认5页包含运行总览、手动操作、参数设置、报警记录、IO，6页再加设备维护。用户可明确改范围；不能自行用趋势页等替换基础页。助手整理具体内容和素材复用，未知真实参数标模拟/待核实，不能从短答猜成已确认。

代表页默认按[布局规则](default-layout-rules.md)展示顶部六类状态信息、其下报警条、左侧/底部两种导航与四种独立色调；左导航不能被报警条覆盖。不同屏幕按实际空间和任务调整主区可见内容，额外空间用于相关信息，不能仅将同一组控件放大。已有明确布局或直接整套的授权按其范围推进，不增加固定审批。

模板、12类原生控件结构和设备母版服务于本项目内容。页面数量、代表页、布局、主题、设备外形与组件组合可以自定义和扩充。原生格式支持范围仍如实列出，不能把缺型转成业务删减。已有资料和局部修改只补相关缺项，不每次重走问卷。

MCGS制作统一走**复用模板资产 → 一份项目源 → 代表页验证 → 展开全套**。方向候选使用可复用的组件结构与素材建模，选定后延续对应的源；代表页和全套的正式预览入口直接带局部编辑及原生复制。扩展布局/渲染器时仍读取同一最终模型，不先交付独立六页HTML、再另建六页原生版。具体建模及入口见[同源构建](shared-project.md)。

## 三阶段的实际成果

| 阶段 | 助手提交 | 确定的内容 |
|---|---|---|
| parameters | 需求摘要、页面内容建议、设备素材及复用计划 | 起步已答的屏幕/行业设备/制作路径；先看方案时总页数可暂待后续选择，不伪造确认 |
| direction | 使用项目内容和复用资产的实际代表页；MCGS项目从同一模型提供预览、局部编辑及复制 | 布局、信息层级、设备表现和色调；可混选或新增 |
| interactive_ui | 从同一项目源展开约定页面，交付当前可编辑、可复制会话入口 | 每页内容、共用框架与适用交互；明确只要效果稿/素材的任务沿其范围 |

由客户确认对应当前版本；已明确委托自主完成的阶段按实际授权推进并记录delegated，不冒充人工确认。委托设计并不自动补足未知行业；客户允许自选演示行业时注明该假设。复用计划随现有参数/方向评审，不另加固定批准轮次。

`project-workflow.template.json`登记上述三阶段的版本、文件摘要、依赖和确认/委托依据，需求与复用细节放在project-brief及page-content-plan的项目副本。范围改变只更新受影响阶段，不要求无关成果重新生产。

这些是内部证据层，不是要求用户额外跑三轮审批。先看方案阶段总页数未定时先保留实际评审文件、消息和草稿范围；最终页数确定后再建立正式workflow。不能为了校验器通过而编造5/6页或人工确认，也不要求用户重复选择未变的风格。

## 记录工具与代表页验证

新项目用[同源项目与覆盖工具](shared-project.md)，在既有方向阶段用代表页验证内容、编辑与复制路径，再批量展开。未贯通时先修复该代表页或逐项保留能力缺项，不用另写独立全套HTML绕开，也不把两套页面的事后对比作为正常工序。局部任务不扩成整套，明确自主委托仍按实际范围推进，不增加固定审批。网页条件和联动是模拟，未实现的原生业务行为另列。

为避免手写出不兼容的流程JSON，`prepare_review_record.py --evidence 项目/review-evidence.json --out 项目/workflow-r1.json`读取实际评审目录、页面清单与真实消息，生成schema1.1的文件哈希、依赖及评审摘要。随后仍用`check_project_workflow.py`核对。具体输入见[证据记录](review-evidence.md)，不让客户填写技术表格。

## HTML阶段就能复制

HTML预览、局部编辑、复制选中控件或完整窗口在预览阶段即可使用。用户已请求复制时启用助手并实际检查；不要求先通过interactive_ui或生成最终PNG包。复制时仅为本次选择即时渲染必要图形/皮肤，文字与动态控件保留原生。复制不表示尚未评审的设计已确认。

## 正式通用素材按需输出

用户需要正式素材包时，在对应设计范围确认或有效委托后，输出通用组件源、独立PNG、文字/布局信息、字体许可说明与清单。只要HTML/原生复制的任务不强制进入最终切图。MCGS只走原生复制，不提供MCGS兼容素材导出、handoff或离线MCP写入交接。

`check_project_workflow.py`核对设计证据与通用素材交付，不对预览即时复制增加审批关口。局部修改仅执行相关范围，未变成果复用。视觉由用户确认；工具默认只修有证据的越界、截断、空图、字段/身份不一致等问题，不反复主观美化重跑。每轮给实际文件或可访问入口，再说明改动与待验证项。
