# 默认精致伪3D设备图鉴

适用项目中确实需要设备插画/工艺设备组件的任务。默认统一为精致的工业产品图鉴风格：伪3D/2.5D、三分之四视角、适度正交或弱透视、真实可识别结构。用户指定扁平/P&ID或其他风格时服从指定风格，不强加3D。

## 需求与复用依据

从 [需求引导](design-intake.md) 获取行业/设备用途、工艺对象、主要部件、连接关系、已有照片/图纸及表现偏好。资料不足时先核实影响结构的项目，未知细节标待核实。纯IO/参数任务无需强加设备插画。

逐对象核对已有母版的结构、端口、朝向、状态、比例和风格：匹配则引用源ID/版本；局部不符则派生项目版本；库中没有就新增独立母版。内置泵/罐仅为起点，不能用它们替换包装机、烘箱等不同设备。设备名、数值、状态灯与管线仍分层，跨项目复用不带入旧文案/信号/工艺假设。复用与新增随需求/方向评审，不另加固定审批。

## 先画流程关系，再逐项图鉴，最后组合

1. **先画系统/设备/零件流程关系图**：按工艺依据先画可编辑HTML/SVG关系图，列出系统、设备及需要独立表达的零件，明确包含层级、连接方向、介质、端口、分支/回路和稳定节点ID。可同图分区表达不同层级，不强制拆成三份文件。关系图可用节点符号表达拓扑，但必须标为流程关系稿，不能冒充设备插画。没有工艺依据的内部结构标待核实，不编造装配或管路。零件范围以本次流程图中应独立表达的实际对象为准，不要求无意义地拆出所有紧固件。
2. **再逐台、逐件画精致伪3D图鉴**：按流程图节点清单，为每个设备/零件制作独立可编辑母版；不省略、不给方框代替设备/零件。相同结构可复用母版，但每个流程节点和实例保留映射。机械外形、独立零件、灯、文字和读数分层。流程2用代表节点验证方向，流程3完成全部图鉴与规格，不只给拼好的全景。
3. **最后按流程图组合工艺画面**：复用同一母版，按端口与层级拼装；外部管线、箭头、灯、文字分别独立。逐项对账“流程节点→图鉴母版/实例→页面组件→独立资产”，不得直接沿用流程关系稿的方框作为最终设备。此顺序属于既有流程1～3，不额外增加客户审批轮次，也不固定行业、六页或某套设备。

确认阶段仍按既有HTML/CSS/SVG流程执行，可用SVG渐变、曲面、前侧面及柔影构造伪3D。正式独立PNG导出在确认后；用户明确要求单项设备生图时按该授权执行。不得以“不准提前生成PNG”为由省略可编辑设备图鉴。

## 统一视觉规范

- 全组同一观察角、朝向基准、光源（建议左上方柔光）、投影方向和材质语言；采用中性金属/烤漆机身，受控的高光、侧面明暗、接触阴影，优先工程可读性，避免卡通玩具或高饱和塑料感。
- 依据实际设备保留具有辨识度的结构：泵的蜗壳/电机/底座/进出口，阀的阀体/法兰/执行器，罐的筒体/端盖/支脚/接口，过滤器的承压壳/检修盖/端口，风机的机壳/叶轮/支架，加药单元的箱体/计量泵/管接头。无工程依据不编造真实型号、连接关系或可操作细节。
- 不是“加一个渐变即精致”：主体轮廓、体积/曲面、功能分区与接口都应可辨，阴影不脏、不压住邻近标签。图鉴在约192～320px级审阅尺寸可检查结构；最终UI缩小时做有意的细节简化，不能用一个34px小图宣称细节图鉴完成。
- 设备机械图单独呈现，不含设备名称、编号、数值、动态灯、品牌字样、外部连接管线或背景卡片。上述元素独立组件叠加。机械自身必要的口/短管接头可以保留，外部管线从命名端口连接。
- 采用真正透明背景，状态组同画布/同锚点/同接口位置。常态/停止/运行不得用多次无约束生图造成机械结构变化；运行/故障灯色在独立状态层表达。
- 生图得到的高分辨率底稿是设备母版/参考，不是目标1:1图的保证。检查实际文件，保留来源，再按明确比例派生最终尺寸；页面拼图不能成为反向裁出设备的母版。

## 可编辑母版起点

`assets/equipment-masters.js` 内置精致伪3D泵与储水箱的SVG母版及端口坐标。可在浏览器调用HMIEquipmentMasters.pump(id)/tank(id)，或Node中require后调用；每个实例提供唯一id。保留比例并按端口锚点组装，不将文字、灯或外部管线画入机械图。它们是可编辑起点，不代替项目型号与结构核对；过滤器、风机等其他设备按内置提示词另行设计，不能统一用水箱替代。

通用build_style_proposal的“工序单元”方框仅表达抽象布局，不是设备图鉴。项目需要设备图时必须接入实际设备组件，不能把那些方框直接当成已交付的设备图。

## 内置提示词

使用 [equipment-prompts.template.md](../assets/equipment-prompts.template.md) 的统一风格母提示词，填入本项目结构、朝向、目标尺寸、接口和阴影留白；按需选用设备类别补充词。生成每台独立设备，不一次生成包含多个不可分离设备的整页。

## 必交付与验收

1. 设备图鉴HTML/SVG：逐设备显示母版、实际UI尺寸预览、组件ID与实例引用；设备名作为图鉴外部可编辑标签。
2. equipment-catalog.json：每设备的ID/类型/源文件、实际宽高、接口锚点、所需状态、机械/灯/标签/读数分层、生成提示词/来源、实际输出路径和检查状态；可复用设备只交一份母版但列全实例。
3. 正式交付独立设备PNG/状态层/可提供矢量源；真实alpha、同尺度/视角/光照、结构识别、端口对齐、最小显示尺寸可读性逐项检查。
4. 不接受空图鉴、只有设备名单、图标占位、方框加名称、同一通用圆柱冒充不同设备、没有端口的简陋几何拼块。达不到时标出具体设备待完善；机械缺项集中修复，精致程度交人工确认，不自行反复美术迭代，不将占位图宣布为精致图鉴。

此规范规定设计产物和检查，不保证任意生图工具必然达到某种质量，也不把生成设备图当工程认证结构图。

## 可执行流程/图鉴覆盖检查

设备类项目使用equipment-catalog schema1.1，模板见assets/equipment-catalog.template.json。process_flow含source_file、nodes、connections；节点{id,name,level:system/equipment/part,parent_id,ports:[端口ID]}，连接{from_node,from_port,to_node,to_port,medium}。先执行`python scripts/check_equipment_flow.py --catalog 项目/equipment-catalog.json --phase flow`；这只检查关系完整性，不代表工程工艺已认证。

每个图鉴equipment条目新增item_kind=equipment/part、flow_node_ids、representation="refined_pseudo_3d"，保留已有独立source_file/source_component_id、尺寸、机械层、状态、实例、接口及外部灯/标签分层。可复用母版映射多个同类流程节点。再执行--phase atlas；缺图鉴、缺节点、重复映射、引用错误或声明方框占位时失败。它不能自动判定美术是否精致，结构辨识/视角/材质/光照与真实可视尺寸仍按上述视觉规范检查。

用户明确指定扁平/P&ID等其他风格时，catalog可记录style_override={representation,user_message,message_ref}，逐项representation与其一致。未给真实用户依据不允许借此把默认精致伪3D降成方框；工具不能认证用户话语，实际上下文由代理负责。
