# 页面内容策划与配方库

用于用户只提供尺寸、色调或页面名称时，主动提出有任务、有数据和有状态的内容方案。配方是设计起点，不是所有设备的固定功能清单；只选择本次范围适用的模块。

## 从简短需求到可确认方案

1. 先提取行业/应用场景、设备用途、工艺关系和操作者任务，再整理已给出的画布、页面范围、公共区域、视觉偏好和交互。像素尺寸与文字比例冲突时指出冲突，以客户确认的原生画布为准，不擅自拉伸。例如1024×600并非精确16:9。
2. 起步按[弹窗引导](beginner-guidance.md)一次收集屏幕、行业设备及先看方案/直接整套。尚无内容清单时，由助手拟定页面及模块；通用设备整套默认五页或含设备维护的六页，用户指定其他范围优先。
3. 将每页整理为“操作任务 → 内容模块 → 数据/单位 → 状态 → 交互”，使用 [内容计划](../assets/page-content-plan.template.md)。区分客户提供、助手建议、模拟数据和工程待核实项。
4. 关键真实工程定义未知时保持待核实；不能为风格预览强制先补齐全部温度、联锁或PLC信息。简短答案不能扩大成虚假已确认。
5. 先看方案者默认先做左侧导航、底部导航两种运行总览布局及四种独立色调，采用同一内容与同一组模拟数据，可在同一HTML中切换八种组合；实际可访问后弹窗选择/修改，选定风格后再弹窗确定5/6页或自定义。不能只放空框和装饰数字。
6. 直接整套者沿用首轮明确范围，先自主核对代表页再继续，不插入未要求审批。各页按任务组织，不能仅换标题复用同一套卡片；公共框架和色调保持一致。正式通用素材按对应确认或有效委托后制作，HTML即时复制不等待切图，详见[项目流程](project-workflow.md)。

若用户仅说“10英寸、1024×600”，先补问行业/设备用途、常用操作和本轮范围；收到设备信息后主动拟页面建议，不把通用设备三页先当作方案。只有客户明确要通用样板或允许自选示例行业时，才按该授权制作演示并标出假设。

## 内容、布局与配色分别维护

| 设计层 | 解决的问题 | 更新位置 |
|---|---|---|
| 公共框架 | 跨页稳定的状态栏、报警区、导航和内容边界 | [页面框架](page-framework.md) |
| 内容配方 | 各页的判断任务、模块优先级、数据和动作 | 下列独立配方文件；新增后在此登记ID/版本/用途 |
| 组件状态 | 每类控件的层次、绑定、状态和演示动作 | [组件使用参考](state-components.md) |
| 几何布局 | 上下/左右分区、内容容量和阅读顺序 | [方案库](style-library.md)及独立布局文件 |
| 配色主题 | 背景、文字、强调及状态表现 | 方案库中的独立主题文件 |

内容计划记录实际使用的配方ID与版本；复制成项目文件后再按设备改动。库新增或修订不自动改变已确认项目，不因色调切换删减内容。新增页面类型时可新增一个配方文件，无需重写技能入口。

## 公共框架的默认建议

客户没有明确公共内容时，顶部默认包含logo、公司名称/设备名称、运行状态、通讯状态、用户登录显示及时间。标识可替换，未知通信显示未连接/待接入，用户未知显示未登录，时间未知保留占位；不伪造真实状态或登录功能。报警条默认在状态栏下方，左导航时仅覆盖右侧业务区，不占侧导航所在列。公共字段的实际位置、无报警表现及跨页保持规则一起在流程1说明、流程2查看。具体边界与自定义见[默认布局规则](default-layout-rules.md)。

## 内容容量与布局起点

不同屏幕按[内容容量规则](default-layout-rules.md)调整可见信息：小屏保留核心工艺/读数/操作，将次级内容收进详情；大屏适度增加有关设备反馈、设定对照、趋势/统计/事件，不能只放大同样少量控件。必需任务仍保留，不用虚构数据填空。下面坐标只适用于底部导航示例；左导航时报警条和主区都从导航右侧开始。

先安排“必须看到/必须操作”，再放“支持判断”，最后考虑装饰。每个模块应能回答一个操作问题；没有相关数据时使用明确空态或移除该建议模块，不用巨大空白卡片补齐。也不通过无关仪表、重复指标或放大标识凑满屏幕。指标数量、表格行数和分区比例随任务及可读性调整，无统一占屏率要求。

下例仅是1024×600、底部导航的坐标起点，单位px，未经目标设备实测；用于展示如何为内容留出真实空间，不是固定标准：

| 区域 | x,y,w,h | 总览内容分配建议 |
|---|---|---|
| 状态栏 | 0,0,1024,56 | 对象/系统、模式、通信、用户、时间 |
| 报警带 | 0,56,1024,28 | 当前报警或明确无活动报警 |
| 导航 | 0,524,1024,76 | 按已确认范围安排导航项 |
| 主区左上 | 16,100,608,180 | 设备对象、状态与适用的简图 |
| 主区左下 | 16,296,608,212 | 关键工艺量；有任务依据时加入仪表/棒图 |
| 主区右上 | 640,100,368,244 | 模式、允许条件、启动/停止等适用操作与回执 |
| 主区右下 | 640,360,368,148 | 本班/今日生产与班次；非生产设备替换为任务相关摘要 |

主区统一外边界为[16,100,992,408]；其余功能页可以在同一边界内换成参数列表、报警表或IO通道网格，不要求沿用总览的内部卡片。六个导航项若采用16px左右留白、8px间隔，则每项约158.7px宽；最终需核对图标、标签、热区和最长文本，不能仅凭算术认定可用。

窗口或长文本容纳不足时，优先减少非必要字段、调整分组和合理滚动，涉及新增页面时回到流程1确认页数；禁止挤压关键触区或裁掉单位。只看坐标无法证明排版合格，应对当前HTML核对正常、异常、长名称、最大数值与空态。

## 策划完成条件

- 每页能说明主要任务，并有对应信息和下一步操作；监控只读页可以没有命令按钮，但须标明只读。
- 已选模块记录数据类型、单位、状态和交互；模拟值与真实工程数据分开，阈值和联锁不凭空补齐。
- 流程2代表页体现真实内容密度和关键组件；流程3页面不是同一模板换标题。
- 适用的关键异常、离线/未知、无数据、权限或条件不足有明确表现，不能只展示正常态。
- 所有图形子层后续纳入 [元素覆盖](asset-coverage.md)，但不因策划资产清单而提前出PNG。
