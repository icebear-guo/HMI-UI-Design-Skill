# MCGS 导出规格（设计与导出侧维护）

此处维护给 MCGS 使用的资产生产约束；MCGS 工程 skill 只消费清单并验证真实工程字段，不重新制定设计规范。

## 命名与像素

- 新资产文件 stem / 图库名匹配 `^[A-Za-z0-9_]+$`，小写 `.png` 扩展名不属于 stem；例如 `nav_overview_s0.png`。避免中文、空格、连字符、点、全角符号、大小写碰撞和 Windows 保留名。
- 新控件标识建议 ASCII 前缀，兼容字母数字中文和下划线；实际显示文字不受文件名字符集限制。页 ID + 控件 ID 唯一，不把不同页的同名控件当同一个。
- 从组件源直接渲染目标像素 1:1：120×40 的组件就导出 120×40，不交付 2×/3× PNG 让工程端猜。既有高倍资产保留原件，若需归一化，作为明确派生步骤记录来源、倍率和哈希。
- 两态/多态同画布同锚点，禁止各态独立紧裁。需要透明时检查实际 alpha 与深浅底边缘，不能用底色或棋盘格假装透明。新组件用 PNG 交付给本适配器；矢量母版另附，不作为图库文件。

## 控件角色与文字归属

| 设计元素 | 目标类型与清单要求 |
|---|---|
| 静态无交互图形 | 原生图片 `0x5009`；不拿按钮代替底图 |
| 导航/动作按钮 | `0x5027`；各按钮独立，状态图和原生文字按态交付；导航写目标页 |
| 独立状态灯、设备状态标记 | 原生指示灯 `0x502a`，需要改变变量才考虑状态切换 `0x5028`；状态图与真实变量语义完整 |
| 多段信息/IO卡片 | 独立布局图片＋按实际行/文本块分开的标签/动态值；底板不当作指示灯，默认不生成灯内多条文字 |
| 按钮单段标题、明确的灯内单段文字 | `text_owner=component`，文字和图片归同一原生控件；不能将按钮标题外置 |
| 灯旁说明、静态标题 | `text_owner=external`，独立标签；不强行写进指示灯两态 |
| 模拟量、设定值、计数 | 数值控件，单位、小数位、范围、样例及变量语义；不写死在标签或 PNG |
| 键盘数字、固定编号、固定时间示例 | 按实际语义记录，不能仅凭有数字就误认成数值输入 |
| 纯布局形状、装饰色块 | 独立层，按已确认目标方案导出 PNG 或给出可复现原生形状参数 |

公共导航、全局通信与报警区域统一放共享组件/公共窗口，业务页只引用；清单明确 common_page_id，不复制到每页。页面数量由项目决定。

## 文字与间距

所有文字输出完整 Unicode 文本、实际字体/回退、字号 px、字重、颜色、对齐、行距和框尺寸。MCGS 的对话框用磅，设计交付仍用 px；写入 LOGFONT 负像素值的细节由工程 skill 处理。

设计阶段就给出最终适配框，不能留待工程端围绕不明锚点反复试。用实际字体测量文字宽并留至少约 10px 的 GDI 余量；粗体可加至 20px 或约 1.1 倍，具体受布局约束。单行高度通常 px+6，多行按行距实算。若余量导致相邻内容相交，回到组件布局调整，而不是只向外扩框。

数值框依据设计的显示范围、符号、小数位、单位及代表性最长值测量；只测初值必须明确验证范围。数值与外部单位、灯与外部说明预留间距。允许的父皮肤覆盖与非预期前景重叠分开声明，不能把所有重叠都豁免。

## 交付与校验

按 [handoff-schema.md](handoff-schema.md) 给出每个组件和每一段文字的机器规格。模板 `assets/handoff-spec.template.json` 表示结构，项目须填入真实源版本、组件/文字和资产；`export_handoff.py` 校验后生成完整 JSON/CSV。配合元素覆盖检查与重组目视检查，不靠清单存在就声称无漏项。


当前MCGS自动工具的数值核心、单位和动作配置先按 [可执行设计配置](executable-design-profile.md)落实；上表描述产品交付结构，不代表每种属性组合都已有自动写入工具。
