# HMI UI 项目需求与客户确认记录

项目范围：完整UI设计 / 大幅改版 / 明确局部任务（填写范围）。

先读取已有资料，只问影响当前阶段的缺项；参数问法见 [参数引导](../references/design-intake.md)，阶段条件见 [项目流程清单](../references/project-workflow.md)。允许“不确定，先建议”，暂定值与客户确认值分别记录。

## 正式切图与最终输出前检查

- [ ] 流程1/流程2/流程3评审以HTML承载，未提前渲染页面或组件PNG，也未用静态图包装代替交互页面。

- [ ] 流程1参数及页面总数已由客户确认，确认对象为当前版本。
- [ ] 流程2最新代表页HTML的布局和色调已由客户确认。
- [ ] 流程3约定数量的全套交互HTML已由客户确认；实际页数/ID与清单一致。
- [ ] 受改动影响的旧确认已失效，相关最新版本已重新确认。
- [ ] 客户确认依据是真实回复；文件生成、默认高亮和工具检查未被当作确认。
- [ ] 流程3已确认HTML的全部可见图形与必要状态均已登记，含人形/装饰图标、独立指示灯及组件子层。
- [ ] 图形均独立导出，或有已验证原生实现/独立矢量的逐项规格与用户确认；没有把独立图形合入背景，源组件对账完整。
- [ ] 正式切片与最终输出仅在以上项均满足后开始。

方向样例与全套交互HTML是前置评审成果，可以先交客户；正式切片、生产PNG及最终交付压缩包不得提前制作。

## 验收与后续变更

- 最终元素清单与文件、必要状态和实例引用逐项核对；缺项/未决/悬空引用不标为完整交付通过。
- 已逐页对照确认HTML检查盘点自身完整，未把机械文件检查当作“所有画面元素均已录入”的证明。
- 文件、纯逻辑、真实浏览器、工程导入和现场任务测试分别记录结果与证据：
- 工程端仍需提供的数据或环境：
- 后续变更内容、受影响阶段、下游确认失效范围与重新确认依据：

不把待填写项、客户沉默、含糊的“继续”或旧版确认视为当前阶段完成；不得代填客户确认原话。状态记录可同步到 [流程记录模板](project-workflow.template.json)。
