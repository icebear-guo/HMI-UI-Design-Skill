# HMI UI 设计

为工业设备触摸屏、操作面板与 SCADA 画面提供可落地的 UI 设计、图像资产和工程交付。先理解操作任务、设备能力与状态逻辑，再确定视觉表达。

## 任务入口

按用户实际请求选择交付，允许组合；用户已要求设计稿或生图时，继续完成相应成果，不以规范文档代替。

## 工作方式

完整UI项目先向客户展示 [流程清单](references/project-workflow.md)，明确以下三项均需客户确认。使用 [项目记录](assets/project-workflow.template.json) 保存实际成果与确认依据，每轮说明当前阶段、HTML入口、待确认项和下一步。

1. **C1 初始参数**：按 [需求引导](references/design-intake.md) 补缺项，汇总原生分辨率宽×高、已提供的屏幕尺寸、导航、色调、语言、必要功能及明确的页面名称和数量。画布以分辨率为准，不另问屏幕比例；不询问工程软件及版本、操作方式或现场光照，也不将这些项列为必填、待补或推进条件。内容不全时按 [页面配方](references/content-library.md) 主动提出每页任务、模块、数据/状态与交互，标明模拟和待核实项；不要求客户先写长提示词，也不自行扩成固定六页。请客户确认汇总与内容计划，确认后才做样例HTML。单项偏好回答不自动成为整份参数确认。
2. **C2 布局与色调HTML**：用同一代表页制作实际HTML候选，方向未定默认3种；已指定方向也至少提交一版当前项目样例。提供入口与版本，请客户确认实际布局、导航和色调。混选或修改后先交最新组合HTML再确认；仅说“暖灰浅色＋左侧导航”不能跳过样例。
3. **C3 全套交互UI HTML**：按C1页面数量和C2方向完成全部UI HTML，提供逐页入口与计数，并按 [交互规范](references/interactive-preview.md) 实现适用功能。先自检，再请客户确认全套当前版本；部分页面确认不放行整套输出。
4. **正式制作与交付**：C1/C2/C3全部有效确认后运行流程检查，才正式渲染PNG、制作双态切片、导出资产并构建最终标注与压缩包，按 [自动验收](references/automatic-acceptance.md) 检查。

三次确认完成前，评审以HTML为主，用原生HTML/CSS/内联SVG及可编辑文字、动态绑定实现。不得先渲染PNG、裁切或批量导出，再把静态图嵌入HTML充当评审稿；不得以验证渲染管线或2倍分辨率为由提前产出PNG。可只读引用用户已提供的位图，不新增页面或组件的PNG渲染。

每阶段先提供实际成果再请求确认；客户未回复、默认高亮、泛泛“继续”、工具检查成功或代理自称“定稿”均不能替代针对成果版本的明确确认。修改影响已确认成果时，重交该阶段及受影响下游。明确只做规范维护、单项素材或局部评审时按范围执行，不冒称完整项目通过。

## 不可丢失的约束

- 可读性和操作任务优先；报警、失联、数据陈旧、命令反馈必须有独立表达，不能只靠颜色。
- 语义色服从项目报警和状态策略；不把“运行必为蓝/绿”、深色背景或 48 px 触区当成所有 HMI 的通用标准。
- 软件停止按钮不作为安全急停的替代；报警确认不代表故障已消除；命令已发送不代表设备已执行。具体控制逻辑须来自项目工程依据。
- 保留原始参考文件与尺寸；裁切、缩放、抠图、转格式等操作产出派生文件并记录。不得把带底色图片或棋盘格图片宣称为真正透明 PNG。
- 新设计的可点击按钮必须包含 `s0/s1` 双状态：`s0` 为常态，`s1` 为清晰可见的交互反馈态。瞬时按钮按下进入 `s1`，松开或取消后恢复 `s0`；导航/切换按钮如需保持选中，单独定义其保持规则。两态同画布、同锚点，不以按钮反馈冒充设备执行成功。
- 区分设计坐标、预览倍率和独立切片像素；导入既有资产时，原有状态编号仍需核实映射，不能反推未说明的工程状态。
- 最终切图从已确认HTML盘点全部可见图形及组件子层：人形、装饰、导航/通信图标、独立小灯/IO LED、状态灯、皮肤和设备图默认独立导出。每项记录角色、实例、状态与文件；原生或静态合并例外须可复现规格和客户确认，不能因CSS/SVG能绘制就省略。文字和动态数据保留原生绑定规格，不能用它们掩盖图形子层缺交。按 [资产覆盖](references/asset-coverage.md) 检查，漏项不宣称完整交付。
- 不把整张生图截图当作可编辑、可绑定的 HMI 工程，也不承诺模型能精确生成文字、尺寸或状态；以实际文件检查为准。

## 交付约定

参数、布局色调样例HTML和全套交互UI HTML按阶段交客户评审；正式PNG、切片和最终交付ZIP在C1/C2/C3全部确认后输出。最终打包助手依赖已有PNG，不得将它倒置为C3评审前置条件。

完整 UI 设计必须按 [交付包规范](references/output-package.md) 输出：可离线操作的 HTML 原型、设计标注、完整页面 PNG 预览、独立 PNG 切片、字体资源及配套清单，连同目录打包压缩。HTML同时提供功能交互和标注查看；标注支持切页、缩放与点选图层，显示坐标、尺寸、字体、颜色。只有静态截图或标注查看器不满足完整交付要求。页数、资产及适用交互按实际任务确定。

使用 [构建清单模板](assets/delivery-manifest.template.json) 组织实际文件；[资产清单](assets/delivery-manifest.template.csv) 记录工程交付信息。字体仅打包已确认可以随交付分发的资源；没有此类文件时说明当前字体配置与缺项。可编辑源文件能提供时一并附上，不把图片包冒称为可运行工程。

只要求规范、提示词、单项素材或局部评审时，按明确范围交付。所有结果标明参数版本、尚未核实的假设、检查范围和工程端待验证事项。切片可追溯到原图和明确坐标；有损放大图不能冒充原生分辨率。

本技能目录自包含，使用相对资源路径。文件名、标题、正文、模板、参数示例与元数据均使用通用表达，不写入提炼出处、公司名称及缩写、具体项目名称或可识别的原始档案信息。导入资料后直接形成通用规则与中性示例，避免将原文或资料目录载入技能。
